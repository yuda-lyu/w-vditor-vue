# 流程_預覽之媒體連結安全

## 觸發

使用者在分割預覽模式編輯內容，編輯區右側之預覽區會把 Markdown 即時顯示為排版後之畫面；內容中指向影片或音訊檔之連結（網址以 mp4、webm、mp3 等結尾）會被預覽區顯示為播放器。本文件涵蓋預覽區顯示此類連結時之安全性：連結網址中夾帶之腳本指令只能當成網址文字，不可被瀏覽器執行；以及正常之影片與音訊連結仍顯示為播放器。

- 入口：示範宿主頁（`spec/設計要點與取捨.md` 第二節），以 `mode=sv` 開啟分割預覽、以 `doc` 指定含連結之文件；預覽區位於編輯區右側。
- 預設狀態：可編輯、頁面同步回寫、回傳即時發出（分割預覽每次輸入即回傳）。
- 緣由：vditor 3.11.3 之預覽於內容淨化（`sanitize`，預設啟用）之後重讀連結網址並未跳脫地組成播放器之 HTML，連結網址含引號時其後之文字成為播放器之屬性，如 `onerror`，播放器載入失敗即執行，使用者不需任何操作（GHSA-x2mx-f527-mxr9，4.0.1 修正，`node_modules/vditor/src/ts/markdown/mediaRender.ts` 之 `replaceMedia` 改以 DOM 屬性設定）。探測：`spec/evidence/2026-11-09-vd01-xss-probe.json`（3.11.3 執行腳本、4.0.1 不執行）。

## 重要流程

- **E2E-001**
  - title: 分割預覽不執行影片連結中夾帶的腳本
  - description: 頁面把含影片連結的內容交給編輯器，連結寫成超連結，網址以 .mp4 結尾，且在引號之後夾帶 onerror 腳本指令。在分割預覽模式，預覽區把該連結顯示為影片播放器，夾帶的指令只是網址的一部分，不會被瀏覽器執行，頁面不受影響；網址無效，影片無法播放，播放器停在載入失敗的狀態。編輯區的原始內容保持不變，載入不會回傳給頁面。適合預覽使用者提交之內容的頁面。
  - flow:
    - 測試資料：文件 `XSS_VIDEO`（標題與一個網址含 onerror 指令、以 .mp4 結尾之超連結），`mode=sv`，頁面同步回寫。
    - 操作：開啟示範宿主頁 → 等載入完成 → 等預覽區出現影片播放器 → 等該播放器載入失敗 → 經過 0.5 秒負向觀察窗 → 讀取頁面全域旗標與播放器屬性。
    - 驗證：
      1. 語意：①預覽區恰有 1 個影片播放器；②頁面全域旗標 `window.__xss` 未被設定（夾帶之指令未執行）；③播放器之屬性名稱只有 controls 與 src，不含 onerror；④播放器之 src 屬性值等於連結網址原文（含引號與 onerror 字樣，只作為網址資料）；⑤頁面未收到回傳；⑥主控台除「影片網址無效之資源載入失敗」外無錯誤。
      2. 視覺：無。
    - 模式：只測分割預覽；理由：所見即所得與即時渲染無預覽區，亦不會把連結轉成播放器（`mediaRender` 僅由 `preview/index.ts`、`previewRender.ts` 與匯出 HTML 呼叫）。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：以 `video.error` 非空為「載入失敗已發生」之同步點（網址對本機站台為 404），其後 0.5 秒為負向觀察窗（失敗事件之處理函式於同一任務佇列執行，觀察窗只用於確認旗標不再變動）。對照：修前 vditor 3.11.3 該旗標被設為 1（`spec/evidence/2026-11-09-vd01-xss-probe.json`、紅燈驗證見 `sgud/exp/experience.md`）。播放器屬性之判定不依賴 `onerror` 是否被執行，故即使載入失敗事件未觸發亦能攔下屬性注入。新增案例。

- **E2E-002**
  - title: 分割預覽不執行音訊連結中夾帶的腳本
  - description: 內容中的連結網址以 .mp3 結尾，且在引號之後夾帶 onerror 腳本指令時，分割預覽之預覽區把它顯示為音訊播放器，夾帶的指令只是網址的一部分，不會被執行，頁面不受影響。與影片連結相同，編輯區的原始內容保持不變，載入不會回傳給頁面。適合預覽使用者提交之內容的頁面。
  - flow:
    - 測試資料：文件 `XSS_AUDIO`（標題與一個網址含 onerror 指令、以 .mp3 結尾之超連結），`mode=sv`，頁面同步回寫。
    - 操作：同 E2E-001，等待對象改為音訊播放器。
    - 驗證：
      1. 語意：①預覽區恰有 1 個音訊播放器；②至⑥同 E2E-001（播放器改為音訊）。
      2. 視覺：無。
    - 模式：只測分割預覽；理由同 E2E-001。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：與 E2E-001 為影片與音訊兩種播放器標籤之對稱路徑（`replaceMedia` 之 `video`、`audio` 分支）。新增案例。

- **E2E-003**
  - title: 分割預覽顯示正常的影片與音訊連結
  - description: 內容中有網址正常的影片連結（以 .mp4 結尾）與音訊連結（以 .mp3 結尾）時，分割預覽之預覽區照常把它們顯示為影片播放器與音訊播放器，播放器帶有播放控制列，網址即為連結所寫的網址。不因加強安全而把正常連結擋掉。適合在文件中嵌入影片或音訊的頁面。
  - flow:
    - 測試資料：文件 `MEDIA_OK`（標題、一個 `/media/a.mp4` 連結、一個 `/media/a.mp3` 連結），`mode=sv`，頁面同步回寫。
    - 操作：開啟示範宿主頁 → 等載入完成 → 等預覽區出現影片播放器與音訊播放器 → 讀取兩個播放器之屬性。
    - 驗證：
      1. 語意：①預覽區恰有 1 個影片播放器與 1 個音訊播放器；②影片播放器之 src 屬性為 `/media/a.mp4`、帶有 controls 屬性；③音訊播放器之 src 屬性為 `/media/a.mp3`、帶有 controls 屬性；④預覽區不再含該兩個超連結（已被播放器取代）。
      2. 視覺：無。
    - 模式：只測分割預覽；理由同 E2E-001。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：與 E2E-001、E2E-002 為「含夾帶指令」與「正常」之對稱路徑，防止以過度過濾修補而擋掉正常連結。播放器之 src 不會被請求之結果不影響斷言（`/media/*` 對本機站台為 404，主控台之資源載入失敗不屬本案之斷言）。新增案例。

- **E2E-004**
  - title: 輸入含影片連結的內容時預覽區不執行夾帶的腳本
  - description: 使用者在分割預覽之編輯區輸入含影片連結的內容，連結網址以 .mp4 結尾且在引號之後夾帶 onerror 腳本指令，輸入完成時預覽區顯示影片播放器，夾帶的指令不會被執行，頁面不受影響；輸入的原始文字保留在編輯區並回傳給頁面。與頁面載入內容相同，輸入過程中預覽區每次更新都不會執行夾帶的指令。適合讓使用者即時撰寫並預覽內容的頁面。
  - flow:
    - 測試資料：預設文件 `ORI`，`mode=sv`，頁面同步回寫；輸入之文字為 `XSS_VIDEO` 之超連結行（以 `docs.json` 之 `XSS_LINK` 為準）。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後輸入換行與該超連結 → 等頁面收到含該超連結之回傳 → 等預覽區出現影片播放器 → 等該播放器載入失敗 → 經過 0.5 秒負向觀察窗 → 讀取頁面全域旗標與播放器屬性。
    - 驗證：
      1. 語意：①預覽區恰有 1 個影片播放器；②頁面全域旗標 `window.__xss` 未被設定；③播放器之屬性名稱只有 controls 與 src；④頁面持有之內容含該超連結原文；⑤主控台除「影片網址無效之資源載入失敗」外無錯誤。
      2. 視覺：無。
    - 模式：只測分割預覽；理由同 E2E-001。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：與 E2E-001 為載入與輸入兩種入口（`setValue` 與 `input` 事件，皆經 `preview.render`）之對稱路徑。輸入以 `keyboard.type` 逐字進入 textarea（vditor 4 起分割預覽之編輯區為 textarea），輸入途中之未完成標籤不構成播放器。新增案例。

## 測試資料

| 變體 | 具名對象 | 取用方式 | 選它的理由 |
|---|---|---|---|
| 影片連結夾帶指令 | `XSS_VIDEO` | `doc=XSS_VIDEO` | 公告所述之超連結形式：網址含引號、空白與 onerror，以 .mp4 結尾 |
| 音訊連結夾帶指令 | `XSS_AUDIO` | `doc=XSS_AUDIO` | 同上，以 .mp3 結尾，涵蓋 audio 分支 |
| 正常影片與音訊連結 | `MEDIA_OK` | `doc=MEDIA_OK` | 防過度過濾之對稱路徑 |
| 輸入入口 | `XSS_LINK`（超連結行） | 鍵盤輸入 | 預覽區隨輸入更新之入口 |

Markdown 寫法之連結（`[文字](x"onerror=…".mp4)`）會被淨化為百分比編碼之網址（`x%22onerror=%22…`），不構成夾帶，故不列為案例（`spec/evidence/2026-11-09-vd01-xss-probe.json` 之 `mdLinkMp4`，修前修後皆未執行）。

## 畫面元素對照

| 區域 | 元素 | 顯示文字／提示文字 | 定義位置 | 出現條件 | 觸發後行為 |
|---|---|---|---|---|---|
| 編輯器右側 | 預覽區 | 內容排版後之畫面 | vditor `ts/preview/index.ts`（`.vditor-preview`） | 分割預覽模式 | 編輯區內容變更即重繪 |
| 預覽區 | 影片播放器 | 瀏覽器內建播放控制列 | vditor `ts/markdown/mediaRender.ts` | 連結網址以 mp4、m4v、ogg、ogv、webm 結尾 | 取代該超連結 |
| 預覽區 | 音訊播放器 | 瀏覽器內建播放控制列 | 同上 | 連結網址以 mp3、wav、flac 結尾 | 取代該超連結 |

## 規則摘要

- 預覽區之播放器由 vditor 依連結網址產生；連結網址一律作為屬性值（DOM 屬性設定），不經 HTML 字串組合，故網址中之引號、空白與 onerror 等字樣只是資料。此為 vditor 4.0.1 之行為（`mediaRender.ts` 之 `replaceMedia`）；3.11.3 以字串插入而可被夾帶（GHSA-x2mx-f527-mxr9）。
- 內容淨化（`options.preview.markdown.sanitize`）預設啟用，組件之內建預設不改動；頁面自行把 `sanitize` 設為 false 者，淨化不再保護內容，屬頁面責任。
- 本流程只涵蓋預覽區（分割預覽）；匯出 HTML 之獨立網頁亦呼叫 `mediaRender`（`ts/export/index.ts`），其行為同一函式，不另設案例。
- 各案例過程中主控台之錯誤只允許「影片或音訊網址無效之資源載入失敗」（網址對本機站台為 404）。
- 視覺：本專案不建像素標準圖（ADR-007），各案例視覺項為「無」。

## 已知落差

本流程目前無未修復之已知落差（2026-11-09）。

- **（已於 vditor 4.0.1 修復）預覽區之媒體連結網址未跳脫，可夾帶屬性執行腳本**（分類：缺陷，已修復；層級：上游 vditor；GHSA-x2mx-f527-mxr9；本套件之修復為相依升至 `vditor ^4.0.1`）
  - 症狀：分割預覽模式之內容含超連結，網址以 .mp4 或 .mp3 結尾並於引號後夾帶 `onerror=…` 時，預覽區產生之播放器帶有該屬性，載入失敗即於頁面執行指令碼，使用者無需操作，預設 `sanitize: true` 亦然。
  - 成因：3.11.3 之 `mediaRender.ts` 於淨化之後以 `getAttribute("href")` 取得解碼後之網址，直接代入 `insertAdjacentHTML` 之字串（`<video controls="controls" src="${url}"></video>`）。
  - 修前重現（2026-11-09）：以 `Vditor.preview` 渲染 `<a href='x" onerror="window.__xss=1" a=".mp4'>v</a>`，3.11.3 全域旗標被設為 1，播放器為 `<video controls="controls" src="x" onerror="window.__xss=1" a=".mp4">`；`spec/evidence/2026-11-09-vd01-xss-probe.json` 之 `old/htmlAnchorMp4`、`old/htmlAnchorMp3`。
  - 修復紀錄：`package.json` 相依 `vditor` 由 `^3.11.3` 改 `^4.0.1`（安裝版 4.0.1）；修後播放器為 `<video controls="controls" src="x&quot; onerror=&quot;window.__xss=1&quot; a=&quot;.mp4">`、旗標未設（`new/htmlAnchorMp4`、`new/htmlAnchorMp3`）。受影響案例：本文件 E2E-001、E2E-002、E2E-004（修前紅、修後綠，見 `sgud/exp/experience.md`）；E2E-003 為正常連結之對稱案例，修前修後皆綠。`dist` 內嵌打包當時之 vditor，使用端須待本套件重新建置並發布後才取得修復（發布由主控處理）。
