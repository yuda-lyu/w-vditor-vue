# 流程_編輯器載入與關閉

## 觸發

頁面嵌入編輯器並給予文件內容後，編輯器先顯示載入圖示，待排版引擎與語系資料載入完成，才顯示文件內容並可編輯。本文件涵蓋開啟、載入期間與載入完成後之關閉、資源較慢或無法取得時之表現。

- 入口：示範宿主頁（`spec/設計要點與取捨.md` 第二節），無主選單。
- 版面：上方操作列（搜尋框、唯讀切換鈕、「取得最新版本」、「恢復上一版」、「清除內容」、編輯器開關鈕、儲存狀態、最近按鍵）、「備忘」輸入欄、編輯器（工具列與編輯區）、頁面持有之內容。
- 預設狀態：可編輯、所見即所得模式、文件 `ORI`、頁面同步回寫。

## 重要流程

- **E2E-001**
  - title: 開啟文件後顯示內容且「復原」停用
  - description: 在嵌入編輯器的頁面開啟一份文件，編輯器先顯示載入圖示，載入完成後即顯示文件內容，工具列的「復原 <Ctrl+Z>」按鈕呈停用狀態。頁面允許編輯時，點擊該按鈕，或點進編輯區後按 Ctrl+Z，內容都維持不變，頁面也不會收到任何變更，亦即開啟時的內容就是復原的起點。開啟本身不改動文件，不需要儲存；若一直停在載入圖示，請確認編輯器所需資源可由頁面設定的位置取得後重新整理頁面。適合開啟既有文件後直接閱讀或接續編輯。
  - flow:
    - 測試資料：預設文件 `ORI`（標題「標題」、段落「第一段內容abc」「第二段內容xyz」），可編輯，頁面同步回寫。
    - 操作：開啟示範宿主頁 → 等載入圖示消失、編輯區出現 → 點擊工具列「復原 <Ctrl+Z>」 → 點擊編輯區並按 Ctrl+End → 按 Ctrl+Z。
    - 驗證：
      1. 語意：①載入完成後編輯區顯示文件內容，空白正規化後所見即所得為「標題 第一段內容abc 第二段內容xyz」，即時渲染與分割預覽為「# 標題 第一段內容abc 第二段內容xyz」；②頁面未收到回傳；③「復原」為停用；④點擊「復原」後內容不變、頁面未收到回傳；⑤按 Ctrl+Z 後內容不變、頁面未收到回傳；⑥頁面持有之內容仍為 `ORI` 原文；⑦未向外部網站請求任何資源；⑧主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：就緒點為 vditor 初始化完成通知（`onEditorReady`），以 `loadValue(true)` 載入並清空復原紀錄；就緒後之負向觀察窗 1.5 秒涵蓋延後寫入復原紀錄之防抖（100 毫秒）。開啟後未點任何處即點停用之「復原」不拋錯（`spec/evidence/2026-10-04-host-probe1.log` 之 P2）。原測試：R01/R02 一般開啟、R02 Ctrl+Z 三模式、R01/R02/R03 即時渲染與分割預覽之開啟部分。

- **E2E-002**
  - title: 輸入後按「復原」回到開啟時內容
  - description: 在編輯區文件末尾輸入文字後，工具列的「復原 <Ctrl+Z>」按鈕轉為可用，點擊一次即撤銷這次輸入，內容回到開啟時的樣子，按鈕再度停用；再點擊也不會越過開啟時的內容，頁面最後收到的內容與開啟時相同。復原會把撤銷後的內容回傳給頁面，是否存回伺服器由頁面決定。適合輸入錯誤時快速恢復成開啟時的內容。
  - flow:
    - 測試資料：預設文件 `ORI`，頁面同步回寫。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後輸入 ZZZ → 等頁面收到結尾為 ZZZ 之回傳 → 停頓 0.6 秒 → 點擊「復原 <Ctrl+Z>」 → 再點擊一次「復原 <Ctrl+Z>」。
    - 驗證：
      1. 語意：①輸入後編輯區為開啟時內容接 ZZZ，「復原」為可用；②第一次復原後編輯區回到開啟時內容且「復原」停用；③第二次點擊後仍為開啟時內容；④頁面最後收到之回傳去除結尾空白後等於 `ORI` 去除結尾空白；⑤主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：三模式按一次即回到開啟時內容（`spec/evidence/2026-10-04-host-probe3.log` 之 P10）；分割預覽之最後回傳結尾多一個換行，故比對忽略結尾空白。原測試：R03、R01/R02/R03 即時渲染與分割預覽之復原部分。

- **E2E-003**
  - title: 網路較慢時仍顯示文件內容
  - description: 網路較慢、編輯器的排版引擎較晚送達時，編輯器會維持載入圖示直到資源到齊，之後照常顯示文件內容，「復原 <Ctrl+Z>」按鈕停用，頁面不會收到變更，畫面也不會出現錯誤。等待期間不需任何操作，也不需要重新整理；若始終停在載入圖示，請確認資源位置後重新整理頁面。適合在內網或連線較慢的環境開啟文件。
  - flow:
    - 測試資料：預設文件 `ORI`；排版引擎（`dist/js/lute/lute.min.js`）之回應延後 1.5 秒。
    - 操作：開啟示範宿主頁 → 等載入完成。
    - 驗證：
      1. 語意：①編輯區顯示文件內容（同 E2E-001 之①）；②「復原」為停用；③頁面未收到回傳；④頁面持有之內容仍為 `ORI` 原文；⑤主控台無錯誤，亦無排版引擎未載入之錯誤（如 Md2VditorDOM）。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：延遲以測試環境之網路路由造成（測試手段，見 `CLAUDE_rulebook.md` 映射）；與 E2E-001 為同一畫面之慢速變體。原測試：R01 lute 延遲（三模式）。

- **E2E-004**
  - title: 頁面自備語系資料時顯示文件內容
  - description: 內網部署時，頁面可把語系資料直接交給編輯器，編輯器就不必另外下載語系檔；在這種設定下開啟文件，載入完成後同樣顯示文件內容，「復原 <Ctrl+Z>」按鈕停用，頁面不會收到變更，也不會出現錯誤。若停在載入圖示，請確認頁面交付的語系資料完整。適合無法連外、需減少外部資源的部署。
  - flow:
    - 測試資料：預設文件 `ORI`；頁面以 `i18n=1` 自備繁中語系資料。
    - 操作：開啟示範宿主頁 → 等載入完成。
    - 驗證：
      1. 語意：①編輯區顯示文件內容；②「復原」為停用；③頁面未收到回傳；④主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得；理由：自備語系資料只改變語系之取得時序，發生於建立各模式編輯區之前（vditor `src/index.ts` 之建構式），與模式無關；三模式之內容顯示由 E2E-001 涵蓋。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：原測試：R01 settings.i18n 頁內首開。

- **E2E-005**
  - title: 關閉後重新開啟編輯器仍顯示內容
  - description: 在頁面上方操作列點擊「關閉編輯器」，編輯器即從頁面移除；再點擊「開啟編輯器」，編輯器重新建立，載入完成後顯示頁面持有的內容，「復原 <Ctrl+Z>」按鈕停用。關閉時尚未回傳給頁面的最後輸入不會再回傳，頁面持有的內容維持關閉前的狀態；重新開啟不需重新整理頁面。適合在分頁、彈窗等反覆顯示與隱藏編輯器的介面中使用。
  - flow:
    - 測試資料：預設文件 `ORI`。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊「關閉編輯器」 → 編輯器消失 → 點擊「開啟編輯器」 → 等載入完成。
    - 驗證：
      1. 語意：①重新開啟後編輯區顯示文件內容；②「復原」為停用；③主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得；理由：重建時資源已載入，差異只在載入時序，顯示與復原起點之模式差異由 E2E-001 涵蓋。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：第二次開啟時 vditor 之排版引擎與語系已在頁內，不再下載。原測試：R02 同頁關閉後再開。

- **E2E-006**
  - title: 同頁兩個編輯器各自顯示內容
  - description: 同一頁面放置兩個編輯器並各給一份文件時，兩個編輯器載入完成後各自顯示自己的文件內容，「復原 <Ctrl+Z>」按鈕皆停用，彼此不互相影響，也不會出現錯誤。適合在同一頁面並列編輯多份文件，例如中英文對照或正文與附註。
  - flow:
    - 測試資料：第一個編輯器為預設文件 `ORI`，第二個為 `SECOND`（標題「第二個」、段落「第二個實例之內容」）；`instances=2`。
    - 操作：開啟示範宿主頁 → 等兩個編輯器皆載入完成。
    - 驗證：
      1. 語意：①兩個編輯區依序顯示「標題 第一段內容abc 第二段內容xyz」與「第二個 第二個實例之內容」；②兩個「復原」皆停用；③主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得；理由：多實例之風險在共用之資源載入與模組層狀態，與模式無關。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：原測試：R01/R02 同頁兩實例。

- **E2E-007**
  - title: 網路較慢時兩個編輯器仍各自顯示內容
  - description: 同一頁面放置兩個編輯器且網路較慢時，兩個編輯器會一起等待排版引擎送達，之後各自顯示自己的文件內容，不會有一個空白或顯示錯誤。等待期間不需任何操作。適合在連線較慢的環境並列編輯多份文件。
  - flow:
    - 測試資料：同 E2E-006；排版引擎之回應延後 1.5 秒。
    - 操作：開啟示範宿主頁 → 等兩個編輯器皆載入完成。
    - 驗證：
      1. 語意：①兩個編輯區依序顯示各自文件內容；②主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得；理由同 E2E-006。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：兩個編輯器共用同一份排版引擎載入（vditor 以腳本識別碼防重複載入）。原測試：R01 同頁兩實例 lute 延遲。

- **E2E-008**
  - title: 載入中收到資料時顯示最新資料
  - description: 頁面開啟後若資料在編輯器載入期間才送達，例如後端回應晚於編輯器建立，編輯器載入完成時會顯示最新送達的資料，而不是一開始的內容；此時「復原 <Ctrl+Z>」按鈕停用，最新資料就是復原的起點，頁面也不會收到變更。資料送達不需任何操作。適合先顯示編輯器、再非同步取得文件內容的頁面。
  - flow:
    - 測試資料：開啟時文件 `AAA`（「AAA初值」），開頁後 50 毫秒送達 `BBB`（「BBB新值」）；排版引擎之回應延後 1 秒。
    - 操作：開啟示範宿主頁 → 等載入完成。
    - 驗證：
      1. 語意：①資料送達當下編輯器仍在載入（前提）；②編輯區顯示「BBB新值」；③頁面持有之內容為「BBB新值」；④「復原」為停用；⑤頁面未收到回傳；⑥主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得；理由：載入期間收到資料只改變就緒時載入之內容，就緒時載入之模式差異由 E2E-001 涵蓋。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：就緒前 `relaValue` 不處理，就緒時 `onEditorReady` 載入當下之內容。與 `流程_頁面更新內容` 之「尚未編輯時頁面送來資料」為同一時序之就緒前與就緒後兩側。原測試：R04 載入期間組件外變更 value。

- **E2E-009**
  - title: 自備語系資料且載入中收到資料
  - description: 頁面自備語系資料，且文件資料在編輯器載入期間才送達時，編輯器載入完成後同樣顯示最新送達的資料，「復原 <Ctrl+Z>」按鈕停用，畫面不出現錯誤。資料送達不需任何操作。適合內網部署並非同步取得文件內容的頁面。
  - flow:
    - 測試資料：預設文件 `ORI`，頁面自備語系資料，開頁後 60 毫秒送達 `BBB`；排版引擎之回應延後 0.8 秒。
    - 操作：開啟示範宿主頁 → 等載入完成。
    - 驗證：
      1. 語意：①編輯區顯示「BBB新值」；②「復原」為停用；③頁面未記錄任何元件錯誤；④主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得；理由同 E2E-004、E2E-008。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：自備語系時 vditor 不等待語系檔，建立編輯器較早，資料送達落在排版引擎到達之前。原測試：R04 settings.i18n 且於 lute 到達前變更。

- **E2E-010**
  - title: 頁面給予空值時顯示空白
  - description: 頁面以空值表示沒有內容時，編輯器顯示空白，不會出現「null」字樣；在空白編輯區輸入文字後，頁面收到的內容只有輸入的文字。之後在頁面上方操作列點擊「清除內容」，編輯器即清空，同樣不顯示「null」。清除會取代編輯區內容，頁面持有的內容隨之成為空值，是否存回伺服器由頁面決定。適合新增文件或後端尚無內容的欄位。
  - flow:
    - 測試資料：開啟時文件為空值（`doc=NULL`），頁面同步回寫。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後輸入 ZZZ → 等頁面收到結尾為 ZZZ 之回傳 → 點擊「清除內容」。
    - 驗證：
      1. 語意：①開啟後編輯區為空白；②載入時頁面未收到回傳；③輸入後每筆回傳皆不含「null」，最後一筆去除空白後為「ZZZ」；④點擊「清除內容」後編輯區為空白；⑤主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得；理由：空值轉為空字串發生於交給編輯器之前（`toMarkdown`），與模式無關。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：原測試：R08 value 為 null。

- **E2E-011**
  - title: 頁面給予數字時以文字顯示
  - description: 頁面交給編輯器的內容若是數字，編輯器會把它當成文字顯示，例如數字 12345 顯示為「12345」，不會停在載入圖示或出現錯誤。顯示不改動頁面持有的內容。適合欄位型別不固定、偶有數字資料的頁面。
  - flow:
    - 測試資料：開啟時文件為數字 12345（`doc=NUM`）。
    - 操作：開啟示範宿主頁 → 等載入完成。
    - 驗證：
      1. 語意：①編輯區顯示「12345」；②主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得；理由同 E2E-010。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：非字串以 `String()` 轉換（`toMarkdown`）。原測試：R08 value 為數字。

- **E2E-012**
  - title: 載入完成時通知頁面一次
  - description: 頁面可在編輯器載入完成時收到一次通知，收到通知時文件內容已經顯示在編輯區，頁面可據此開始後續動作，例如聚焦或取得編輯器設定；同一個編輯器只通知一次。通知不改動內容。若始終沒有收到通知，表示編輯器停在載入圖示，請確認資源位置。適合需要在編輯器就緒後才執行的頁面邏輯。
  - flow:
    - 測試資料：預設文件 `ORI`；頁面記錄載入完成通知（`after=1`）。
    - 操作：開啟示範宿主頁 → 等載入完成。
    - 驗證：
      1. 語意：①載入完成通知恰一次；②通知當下編輯區已顯示「標題 第一段內容abc 第二段內容xyz」；③通知之接收者為 vditor 合併後之設定（含編輯模式）；④主控台無錯誤。
      2. 視覺：無。

## 規則摘要

- 就緒前不寫入內容；就緒時載入當下之內容並作為復原起點（`spec/設計要點與取捨.md` ADR-002）。
- 頁面持有之內容於載入時不被組件改動（載入不回傳）。
- 關閉時尚未回傳之最後輸入不再回傳（JSDoc 之 `input` 事件說明）。
- 各案例過程中主控台不得出現錯誤，E2E-017、E2E-018、E2E-022、E2E-023、E2E-025、E2E-026、E2E-027 除外（資源失敗與設定錯誤本身會留下瀏覽器、vditor 或組件記錄之錯誤）。
- 載入中關閉（ADR-008）：vditor 無取消初始化之介面，組件於其初始化完成前銷毀時不呼叫 vditor 之銷毀，改由 `releaseCreating` 寫入 vditor 自身之已銷毀旗標（語系檔送達後不再初始化、不再請求排版引擎）、抑制語系檔於關閉後才失敗之訊息、解除已綁定之所見即所得捲動監聽；排版引擎於關閉後才送達者，由 `onEditorReady` 於 vditor 初始化完成時補做完整銷毀。
- 監聽殘留之量測：以 Chrome DevTools Protocol 取 window、document 與 visualViewport 上各事件型別之監聽數，與開頁時不顯示編輯器之對照頁比對；Playwright 於頁面主環境首次執行偵測等待時會於 window 注入一組命中檢查監聽，對照頁亦以偵測等待確認掛載後再量，使兩頁同含該組監聽（`test/tools/e2e-setup.mjs` 之 `globalListeners`，`spec/evidence/2026-10-04-destroy-probe5.log`）。
- 資源載入進度以網路請求之發出、送達與失敗觀察（`openCase` 之 `assets`），作為「已進入某載入階段」之前提與「關閉後不再下載」之驗證，不以固定等待推定。
- 頁面另給之設定內容與快取內容，於就緒時皆被頁面交給編輯器之內容取代（JSDoc `value`）。
- 工具列「匯出」之 PDF 項需於 iframe 內另取外部資源，組件固定移除（JSDoc 說明、`removeExportPdf`）。
- 視覺：本專案不建像素標準圖（ADR-007），各案例視覺項為「無」。

## 已知落差

- **排版引擎始終無法取得時關閉編輯器，window 殘留 1 個 scroll 監聽（已修復（附修復紀錄）；發現於 2026-10-04，已於 2026-10-04 修復）**：原載：排版引擎請求中止後點擊「關閉編輯器」，window 之 scroll 監聽數由對照頁之 0 變為 1（`spec/evidence/2026-10-04-host-probe2.log` 之 P8 lute）；語系失敗時無此現象（同檔 P8 i18n）。成因：vditor 建構時即建立所見即所得編輯區並綁定 window 捲動監聽（`node_modules/vditor/src/ts/wysiwyg/index.ts` 之 `bindEvent`），組件於載入中關閉時把銷毀延到初始化完成時（`WVditorVue.vue` 之 `beforeDestroy`、`onEditorReady`），初始化永不完成則永不銷毀。同類另有：語系晚到而排版引擎無法取得、頁面自備語系而排版引擎無法取得、反覆開關（每次多 1 個）、編輯模式不合法（`spec/evidence/2026-10-04-destroy-probe1-cur.log` 之 S1、S2、S5、S6，`2026-10-04-destroy-probe4-cur.log` 之 e3）。修復紀錄：①版本：w-vditor-vue 1.0.17 之原始碼（2026-10-04，尚未發布）；②改動點：`WVditorVue.vue` 之 `beforeDestroy` 於初始化未完成時改呼叫新增之 `releaseCreating`（寫入 vditor 之已銷毀旗標、覆寫其錯誤提示、解除所見即所得之捲動監聽），延後銷毀保留於 `onEditorReady`（ADR-008）；③產物證據：e2e 以 rollup 即時編譯現行原始碼（`test/tools/e2e-setup.mjs` 之 `buildComponent`），`dist` 由發布流程產製；④實機證據：以定稿原始碼探測 `spec/evidence/2026-10-04-destroy-probe2-final.log`、`2026-10-04-destroy-probe3-final.log`、`2026-10-04-destroy-probe4-final.log`（上列情形皆為 0），紅燈驗證 `spec/evidence/2026-10-04-destroy-redrun-pre.log`（修正前原始碼 E2E-014、E2E-015 三模式、E2E-017、E2E-025、E2E-026、E2E-027 共 8 條轉紅，其餘 27 條通過）與 `2026-10-04-destroy-redrun-fix.log`（35 條全數通過）；⑤受影響案例：E2E-017 改為嚴格比對並移除 pending，E2E-014 補⑦，E2E-015 補載入階段前提、關閉當下之量測（⑦）並擴為三模式，新增 E2E-025～027，各案例之監聽量測擴為 window、document 與 visualViewport 之全部事件型別；本專案不建標準圖；⑥轉交來源：無（vditor 無取消初始化之介面等上游事項見 `spec/設計要點與取捨.md` 第六節）。
- **排版引擎載入失敗時主控台出現未捕捉之 Promise 拒絕（設計事實（記錄備查）；發現於 2026-10-04）**：vditor 載入 lute 之 `addScript(...).then(...)` 無 `catch`（`node_modules/vditor/src/index.ts` 之 `init`），中止請求時主控台出現 `[pageerror] Event`（`spec/evidence/2026-10-04-host-probe2.log` 之 P8 lute）。使用者可觀察之後果：只在主控台，畫面停在載入圖示。語系檔送達前即關閉者不再請求排版引擎，故不出現此錯誤（E2E-014④⑦）。層級：上游 vditor 3.11.3（第三方開源套件），記錄備查。
- **設定錯誤使 vditor 於建立編輯區中途拋錯時，關閉後可能殘留 1 個 window scroll 監聽（設計事實（記錄備查）；發現於 2026-10-04）**：vditor 建立所見即所得編輯區時即綁定捲動監聽，之後才讀取其他設定；設定錯誤使其中途拋錯時，有兩種情形組件無從解除：①頁面自備語系時 `init` 於 vditor 建構式內同步執行，錯誤自建構式拋出，組件取不到 vditor 實例，例如工具列子選單含不存在之項目名稱（`node_modules/vditor/src/ts/toolbar/index.ts` 對子項目寫入 `level`）、`settings.resize` 為 null（`src/index.ts` 之 `init` 讀取 `resize.enable`；設定合併保留 null，`src/ts/util/merge.ts`）；②錯誤發生在所見即所得編輯區之建構式內、綁定捲動監聽之後，例如 `settings.comment` 為 null（`src/ts/wysiwyg/index.ts` 先 `bindEvent` 再讀 `comment.enable`），該編輯區物件未被保存，語系由 vditor 下載亦同。其餘中途錯誤（由 vditor 下載語系、所見即所得編輯區已建立者）組件可解除。由 vditor 下載語系時，這類錯誤被其語系載入之 `catch` 接住而顯示「GET …404」之誤導訊息。證據：`spec/evidence/2026-10-04-destroy-probe3-final.log` 之 P-b（殘留 1）、P-c（0，誤導訊息出現），`2026-10-04-destroy-probe6-cur.log`、`-final.log` 之 X2（修正前後皆殘留 1）。使用者可觀察之後果：只在設定錯誤時發生；編輯器停在載入圖示（主控台有錯誤或頁面出現誤導之語系訊息），每開關一次多 1 個捲動監聽；修正設定即不發生。層級：上游 vditor（初始化中途失敗不清理已綁定之監聽），記錄備查。
- **初始化介面時於綁定視窗縮放監聽後拋錯，關閉後殘留 1 個 window resize 監聽（設計事實（記錄備查）；發現於 2026-10-04）**：例如編輯模式不合法且關閉打字機模式、`settings.value` 不是字串（`node_modules/vditor/src/ts/ui/initUI.ts` 之 `afterRender` 先綁定縮放監聽並回傳初始內容，`setEditMode` 把非字串之回傳值當事件呼叫 `preventDefault` 而拋錯）；此時初始化永不完成。該監聽存於 vditor 模組層之單一變數，組件若自行移除可能移除同頁其他編輯器者（他編輯器於其後初始化時會取代該變數），故不移除；下一個編輯器初始化時 vditor 會先移除該變數中之監聽，不會累積；捲動監聽仍由組件解除。證據：`spec/evidence/2026-10-04-destroy-probe4-final.log` 之 e4、`2026-10-04-destroy-probe6-final.log` 之 X3（修正前另殘留 1 個 scroll，`-cur.log`）。組件預設啟用打字機模式時編輯模式不合法之錯誤發生在綁定之前，無此殘留（E2E-027）。層級：上游 vditor，記錄備查。
- **同頁多個編輯器時，只有最後完成初始化者有視窗縮放處理（設計事實（記錄備查）；發現於 2026-10-04）**：vditor 以模組層單一變數保存視窗縮放監聽，每次初始化先移除前一個再綁定自己的，任何已就緒之編輯器銷毀時亦移除該變數中之監聽（`node_modules/vditor/src/ts/ui/initUI.ts` 之 `UIUnbindListener`、`src/index.ts` 之 `destroy`）。證據：兩個就緒之編輯器只有 1 個 vditor 之縮放監聽（`spec/evidence/2026-10-04-destroy-probe1-cur.log` 之 S8）。使用者可觀察之後果：失去縮放處理之編輯器於視窗跨越行動版寬度門檻時不重算內距、打字機模式之底部距離不更新；組件預設 `preview.maxWidth` 為 1e10，內距一般恆取最小值，實際畫面差異未實測。載入中關閉某編輯器而其排版引擎晚於另一編輯器送達時（例如以 key 重建組件），被關閉者延後之初始化亦會移除存活者之縮放監聽；測試環境之延遲依請求順序送達，無法重現此反序，示範頁亦無法只關閉其中一個編輯器，未設案例。層級：上游 vditor，記錄備查；組件若改為預載資源後才建立 vditor 可消除後者（ADR-008 之方案 P），本次不採。
