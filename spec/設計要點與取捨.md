## 二、示範宿主頁（各流程共用之入口）

`test/host/index.html` 扮演「嵌入編輯器之頁面」（以下稱頁面），文件內容取自 `test/host/docs.json`（測試端讀同一檔）。頁面之行為於開頁時以網址參數設定（屬前置），案例之操作只經頁面之按鈕、快捷鍵與編輯器之真鍵盤滑鼠。

### 畫面元素

| 區域 | 元素 | 顯示文字 | 觸發後行為 |
|---|---|---|---|
| 上方操作列 | 搜尋框 | 提示文字「搜尋」 | 一般輸入框；Tab 鍵移動焦點之起點 |
| 上方操作列 | 唯讀切換鈕 | 可編輯時「設為唯讀」，唯讀時「設為可編輯」 | 切換編輯器之唯讀 |
| 上方操作列 | 「取得最新版本」 | 同左 | 依序取得伺服器上之下一個版本並交給編輯器（預設依序為 `PULL1`、`PULL2`） |
| 上方操作列 | 「恢復上一版」 | 同左 | 捨棄頁面版本紀錄之最新一版，以其前一版交給編輯器；版本紀錄為開啟時之內容與每次收到之回傳 |
| 上方操作列 | 「清除內容」 | 同左 | 頁面以空值（null）表示無內容並交給編輯器 |
| 上方操作列 | 編輯器開關鈕 | 顯示時「關閉編輯器」，關閉時「開啟編輯器」 | 移除或重新建立編輯器 |
| 上方操作列 | 儲存狀態 | 儲存中「上傳中…」，完成「已儲存」 | 顯示 Ctrl+S 儲存之進度 |
| 上方操作列 | 最近按鍵 | 「最近按鍵：」接頁面最近收到之按鍵名 | 頁面於 document 之 bubble 階段收到按鍵時更新 |
| 操作列下方 | 「備忘」輸入欄 | 預設文字 PASTE | 一般輸入欄，供複製文字 |
| 中央 | 編輯器 | 工具列與編輯區 | 受測組件，高度 300 像素 |
| 編輯器下方 | 頁面持有之內容 | 頁面目前持有之 markdown 原文 | 頁面依回寫方式更新 |

### 快捷鍵（頁面於 window 之 capture 階段處理，先於編輯器，處理後不再傳遞）

- Ctrl+S：儲存。儲存狀態顯示「上傳中…」；依設定於上傳期間把編輯器設為唯讀；伺服器回應後依設定寫回內容；完成後顯示「已儲存」並恢復可編輯。
- Alt+F：聚焦搜尋框（頁面程式移動焦點之代表）。

### 頁面行為參數（開頁時設定）

| 參數 | 意義 |
|---|---|
| `mode` | 編輯模式：`wysiwyg` 所見即所得、`ir` 即時渲染、`sv` 分割預覽 |
| `doc` | 開啟之文件（`docs.json` 之鍵；`NULL` 為空值、`NUM` 為數字 12345），預設 `ORI` |
| `editable=0` | 開啟唯讀文件 |
| `i18n=1` | 頁面自備語系資料交給編輯器（內網部署用法） |
| `lang` | 編輯器語系設定（預設 `zh_TW`） |
| `svalue` | 編輯器設定中另給之內容（`docs.json` 之鍵） |
| `cache`、`cacheSeed` | `id` 啟用快取（識別碼 `e2e-cache`）、`noid` 啟用快取但不給識別碼；開頁前寫入快取之內容 |
| `focusLog=1`、`after=1`、`cbLog=1` | 記錄編輯器之聚焦／失焦通知、載入完成通知、選取／取消選取／按鍵／Esc／Ctrl+Enter 通知 |
| `keyHint`、`hintTimeDetect` | 提示區之觸發字串（多組以逗號分隔）、編輯器回傳之防抖毫秒數（預設 100） |
| `writeMode` | 頁面收到回傳後之回寫方式：`sync` 同步（雙向綁定）、`micro` 下一個微任務、`debounce300` 停止回傳 300 毫秒後、`trim` 修整兩端空白、`none` 不回寫、`delay1000` 每筆延後 1 秒（只供探索） |
| `instances=2`、`shared=1` | 另顯示第二個獨立編輯器、另顯示共用同一份內容之編輯器 |
| `hide=1` | 開頁時不顯示編輯器 |
| `dataAt`、`dataDoc` | 開頁後 `dataAt` 毫秒才收到資料 `dataDoc`（後端資料延遲到達） |
| `permAt`、`permTo` | 開頁後 `permAt` 毫秒才收到權限（`permTo=1` 可編輯、`0` 唯讀） |
| `saveLock`、`saveReply`、`saveReplyAt`、`serverDoc` | Ctrl+S 之上傳：上傳期間唯讀之毫秒數（0 不鎖定）、伺服器回應後之寫回（`none` 不寫回、`echo` 回傳上傳內容並於結尾補換行、`echoCrlf` 回傳上傳內容並改為 CRLF 換行、`server` 回傳 `serverDoc`，預設 `SERVER`）、回應時間 |
| `pull` | 「取得最新版本」依序取得之文件鍵 |

## 三、跨流程設計決策（ADR）

- **ADR-001 組件定位：單一編輯者之輸入組件**（Status：Accepted，2026-10-04 使用者裁決）
  - Context：第二輪曾為支援父層延遲回寫於組件內保留回拋紀錄，衍生之邊界被稱為限制，使用者否決。
  - Decision：組件與原生 input、CKEditor／TinyMCE／Quill 官方 Vue 封裝同類，只做三件事——編輯器就緒時載入頁面給予之內容並顯示、內容一變更即回傳、依唯讀設定鎖定（鎖定一致性由組件維持）。回傳資料之去向（同步其他組件、上傳伺服器）、上傳期間之鎖定、多組件單向同步、延遲或亂序回寫之協調屬頁面；多組件或多人共編須頁面與組件層皆支援 CRDT，組件目前不支援。
  - Consequences：頁面延遲回寫舊值時以該值為準載入（可能使尚未回寫之輸入錯置），與其他封裝一致，列設計事實（見〈裁決紀錄〉）。
  - Affected：editing、parent-update、readonly。
- **ADR-002 載入時機與復原起點**（Accepted）：以 vditor 之初始化完成通知為就緒點，就緒時載入當下之內容（含載入期間頁面才給予者）並作為復原起點；就緒前不寫入。`WVditorVue.vue` 之 `mounted`、`onEditorReady`、`loadValue`。Affected：load、parent-update。
- **ADR-003 回寫判斷**（Accepted）：頁面給予之內容等於最後回傳值或編輯器當前內容（忽略結尾空白與換行符差異）即視為回寫而不重載；其他一律以頁面之內容為準載入，未編輯時新內容為新的復原起點、已編輯時保留復原歷史。`isEcho`、`relaValue`。Affected：editing、parent-update、key-hint。
- **ADR-004 唯讀完整性由組件於事件層補齊**（Accepted）：vditor 之停用只停用工具列並設編輯區不可編輯，其點擊、按鍵、焦點與輸入處理皆不檢查唯讀；組件於根元素之 capture 階段攔截（`guardLock`，事件清單 `LOCK_EVENTS`），並以 MutationObserver 改回被重新啟用之工具列與編輯區（`watchLock`、`enforceLock`）。Affected：readonly、readonly-focus、key-hint。
- **ADR-005 唯讀之焦點語意同原生 readonly**（Accepted）：Tab 鍵可進入唯讀編輯區以捲動、聚焦連結與核取方塊；滑鼠、觸控等非鍵盤取得之焦點延後釋放；焦點在唯讀編輯區內時其按鍵不往外傳遞（頁面於 capture 階段仍收得到）。`guardLock`、`releaseFocus`、JSDoc `editable`。Affected：readonly-focus。
- **ADR-006 提示區插入只移除游標前本次輸入之觸發字串**（Accepted）：不以全文搜尋觸發字串，不整份取代內容，以 vditor 公開之插入方法插入。`removeHintTrigger`、`insertValue`。Affected：key-hint。
- **ADR-007 e2e 不建像素標準圖**（Accepted，2026-10-04）：
  - Context：e2e 技能 §0 依專案有無像素比對決定全量適用或只採通用原則；本專案舊 e2e 無像素比對；組件庫無操作手冊讀者；同組織組件庫 w-component-vue（2026-09-29～10-01）之 e2e 亦只做語意斷言。
  - Decision：只採通用原則，每案例以語意斷言（畫面文字、工具列狀態、焦點、頁面收到之回傳）為驗證；各案例視覺項寫「無」。
  - Consequences：版面、圖示與配色之回歸不在 e2e 範圍；若日後要補像素標準圖，須另行授權產圖並依技能 §7 審圖。
  - Affected：全部流程。
- **ADR-008 載入中關閉：依 vditor 之初始化進度釋放**（Accepted，2026-10-04）：
  - Context：vditor 無取消初始化之介面。其初始化分三段：語系檔載入前（尚無內部物件）、語系檔已到而排版引擎未到（已建立各模式編輯區並綁定 window 捲動監聽）、排版引擎送達後（同步初始化介面、綁定視窗縮放監聽並發出完成通知）。其 `destroy` 於第一段呼叫會拋錯；於第二段呼叫則其 `UIUnbindListener` 會移除同頁其他編輯器之縮放監聽（模組層單一變數），且排版引擎事後送達時仍會初始化並重新綁定。原作法把載入中之銷毀延到初始化完成時（`onEditorReady`），初始化永不完成時殘留捲動監聽（`流程_編輯器載入與關閉`〈已知落差〉已修復之條目）。同類封裝：TinyMCE 官方 Vue 封裝先載入核心、`init` 時才依選擇器解析目標元素，元素已移除即不建立（`@tinymce/tinymce-vue` 3.2.8 `Editor.js`；`tinymce` 5.10.9 之 `init`），其核心於 `remove` 時設 `removed` 並於非同步載入樣式與初始內容後檢查之（`tinymce.js` 之 `remove`、`initEditorWithInitialContent`）——即「非同步返回後檢查已處置」；同組織 w-ckeditor-vue 內含之 CKEditor 5 Vue 2 封裝（fork 自官方 ckeditor5-vue2）只在建立完成後保存實例、`beforeDestroy` 只銷毀已保存者，建立中被銷毀者其事後建立之實例不由封裝銷毀（`src/ckeditor.mjs`；核心是否另有處置未讀）。2026-10-04 經 Claude Opus 5.5 兩名與 GPT-6.1 sol 一名獨立審查。
  - Decision：初始化未完成即銷毀時呼叫 `releaseCreating`：寫入 vditor 之 `isDestroyed`（vditor 自身於 `destroy` 設定、`init` 開頭檢查之旗標，語系檔送達後 `init` 直接返回、不再請求排版引擎）、以實例屬性覆寫 `showErrorTip`（語系檔於關閉後才失敗時不附加訊息）、vditor 已建立內部物件時呼叫 `wysiwyg.unbindListener` 解除捲動監聽；排版引擎於關閉後才送達者仍由 `onEditorReady` 補做完整銷毀。
  - 未採方案：A 關閉時即呼叫 `destroy` 並重設 `options.after`（第一段拋錯；第二段呼叫時其 `UIUnbindListener` 移除當下變數中之縮放監聽——頁面首次載入排版引擎期間先後建立兩個編輯器時，先建立者之排版引擎先送達而已就緒、後建立者仍在第二段，此時關閉後建立者即移除先建立者之縮放監聽；又須寫入 vditor 內部之 `options.after`）；P 組件預載語系與排版引擎後才建立 vditor（同 TinyMCE 之作法，可再消除「載入中關閉之編輯器日後初始化而搶走縮放監聽」與延後銷毀時之同步圖示下載，代價為複製 vditor 之設定合併規則與內部 script 識別碼、語系失敗時 vditor 之訊息不再出現須另行處理，改動面最大）；只預載排版引擎（只依賴內部識別碼 `vditorLuteScript`，保留語系訊息，第二段縮為同一輪微任務，第一段仍需旗標）；只記錄不修。P 與只預載排版引擎列為後續選項。
  - Consequences：寫入 vditor 之兩個 private 成員（TypeScript 之 private 於執行期為一般屬性，已確認 `dist/index.js` 未改名）；vditor 升版改名時由 `load` E2E-014⑦（關閉後不得請求排版引擎）與 E2E-025（關閉後不得出現語系訊息）攔下。本方案不處理之情形：①設定錯誤使 vditor 於建立編輯區中途或初始化介面時拋錯（組件取不到實例、未保存之編輯區、已綁定之縮放監聽）；②同頁多編輯器之縮放監聽（上游單一變數）——兩者列於 `流程_編輯器載入與關閉`〈已知落差〉；③呼叫端於 vditor 之同步回呼（例如自訂渲染）內、組件就緒處理期間直接銷毀組件（`$destroy`）時，`beforeDestroy` 視為初始化未完成而只做本方案之釋放，vditor 不被完整銷毀而殘留 1 個縮放監聽（控制流：`mounted` 之 `after` 回呼 → `onEditorReady` → `loadValue` → vditor 渲染時同步呼叫自訂渲染）——非正常用法、未觀察到，記錄不處理。就緒處理失敗（stage `failed`，例如自訂渲染於載入內容時拋錯）之關閉與就緒後關閉同走 vditor 之 `destroy`（`load` E2E-016 之路徑）。
  - Affected：load。

## 五、共通約定

- **語系**：單一語系，編輯器使用繁體中文（vditor `zh_TW`）；組件無自有介面文字，各案例無雙語 bullet。
- **編輯模式**：三種模式（所見即所得、即時渲染、分割預覽）為各案例之變體迴圈，對應語系迴圈之位置；某模式前提不成立時於案例〈模式〉寫明排除理由。
- **標準圖**：不建（ADR-007），各案例視覺項寫「無」。
- **執行前置與副作用清理**：無資料庫與後端；每案例開全新瀏覽器；元件以現行原始碼編譯至 `test/_tmp/<流程代號>/`，該測試檔結束時刪除並回驗目錄不存在；剪貼簿隨瀏覽器關閉而消失；不寫出其他檔案。
- **等待**：以使用者可觀察之結果偵測（編輯區文字、頁面收到之回傳、儲存狀態、提示區出現）；固定等待只用於負向觀察窗，並註明涵蓋之計時——編輯器回傳與寫入復原紀錄之防抖預設 100 毫秒（案例設 600 毫秒者另計）、提示區偵測輪詢每 50 毫秒。
- **復原前停頓**：vditor 以防抖寫入復原紀錄，分割預覽之回傳於每次輸入同步發出、寫入復原紀錄卻另於 100 毫秒後（`node_modules/vditor/src/ts/sv/process.ts` 之 `processAfterRender`），頁面載入新內容後亦同，皆無使用者可觀察之訊號；案例於按「復原」或 Ctrl+Z 前停頓 0.6 秒（防抖 600 毫秒者停頓 1.2 秒），對應使用者輸入後之自然停頓。
- **訊息**：組件不顯示提示訊息；工具列提示文字取自 vditor 繁中語系檔，格式為「名稱 <快捷鍵>」，例如「復原 <Ctrl+Z>」（`spec/evidence/2026-10-04-host-probe1.log` 之 P1）。
- **錯誤**：各案例過程中瀏覽器主控台不得出現錯誤，案例另有說明者除外。
- **資源**：編輯器所需資源（排版引擎、語系資料、圖示）一律由頁面設定之位置取得；測試環境阻擋並記錄所有對外請求。
- **事實來源**：只認現行程式碼（含 `node_modules` 內 vditor、w-component-vue 之原始碼）與實機；舊說明文件不作依據。
- **證據目錄**：`spec/evidence/`，檔名帶日期與探測名，不覆蓋；引用格式為檔名＋段落代號（如 P1、B14）。
- **description 撰寫風格**：寫給嵌入此編輯器之頁面的使用者與開發者閱讀之操作說明；骨架「在哪裡、做什麼、看到什麼、什麼時候用得上」，讀完能答入口與權限、必要前置、不可逆效果、是否已寫入、成功識別、失敗如何處理六問；不寫程式位置、識別字、案例編號與測試語彙；按鈕名與提示文字照畫面原文。
