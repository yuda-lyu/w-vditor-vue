# 流程_唯讀時之焦點

## 觸發

編輯器唯讀時，焦點的行為與網頁原生的唯讀輸入框相同：可以用 Tab 鍵進入編輯區以捲動或移到其中的連結、核取方塊，但滑鼠點擊取得的焦點不會留在編輯區內；焦點在唯讀編輯區內時，按鍵不會改動內容，也不會傳到頁面的一般按鍵處理，頁面以 capture 階段註冊之快捷鍵仍收得到。本文件涵蓋鎖定當下、Tab 鍵進出、滑鼠點擊與頁面程式移動焦點。內容不可改動之其他面向見 `流程_唯讀鎖定`。

- 入口：示範宿主頁（`spec/設計要點與取捨.md` 第二節），使用搜尋框（Tab 鍵起點）、Ctrl+S 儲存、Alt+F 聚焦搜尋框、「最近按鍵：」顯示。
- 預設狀態：可編輯、文件 `ORI`。

## 重要流程

- **E2E-001**
  - title: 打字中儲存鎖定時編輯區失焦且快捷鍵無效
  - description: 在編輯區打字時按 Ctrl+S 儲存，頁面於上傳期間把編輯器設為唯讀；此時編輯區立即失去焦點，之後再按標題、切換編輯模式等快捷鍵或打字，內容都不會改變，頁面也不會收到變更；頁面只會收到一次失焦通知。上傳完成、頁面顯示「已儲存」後恢復可編輯。適合儲存期間鎖定編輯、避免使用者誤以為仍可輸入的頁面。
  - flow:
    - 測試資料：預設文件 `ORI`；頁面記錄聚焦與失焦通知（`focusLog=1`）；儲存時上傳期間唯讀 3 秒，伺服器不寫回。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後輸入 a → 等頁面收到結尾為 a 之回傳 → 按 Ctrl+S → 等編輯區不可編輯 → 按 Ctrl+Alt+2 → 按切換編輯模式之快捷鍵（分割預覽按 Ctrl+Alt+7，其他按 Ctrl+Alt+9）→ 輸入 Z → 經過 0.8 秒負向觀察窗。
    - 驗證：
      1. 語意：①鎖定後焦點不在編輯區內；②編輯區內容不變（未改為標題、未切換模式）且結尾為 a；③編輯區不可編輯；④頁面未收到新的回傳；⑤鎖定後頁面恰收到 1 次失焦通知、無聚焦通知；⑥主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：鎖定時之失焦仍交 vditor 處理以保存選取範圍，故失焦通知由 vditor 發出恰一次（`applyEditable` 之 `blurEditor`）；之後之按鍵落在頁面。Ctrl+S 由頁面於 window 之 capture 階段處理，不傳至編輯器。原測試：R15 打字中鎖定（三模式；原以程式鎖定，今改為 Ctrl+S 儲存）。

- **E2E-002**
  - title: 唯讀時以 Tab 鍵移入編輯區後按鍵不改內容
  - description: 唯讀文件可以用 Tab 鍵把焦點移進編輯區，例如移到其中的核取方塊或連結；此時按 Enter、刪除、空白鍵、一般字元、標題或切換編輯模式等快捷鍵，以及 Tab 鍵，內容都不會改變，頁面不會收到變更，也不會出現錯誤。唯讀時不改動文件。適合以鍵盤瀏覽唯讀文件的使用者。
  - flow:
    - 測試資料：文件 `RO`（標題、未勾與已勾之待辦、含連結之段落、「末段文字」），唯讀。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊搜尋框 → 連按 Tab 直到焦點位於編輯區內 → 依序按 Enter、Ctrl+Alt+2、Backspace、Delete、空白鍵、Z、切換編輯模式之快捷鍵、Tab → 經過 1 秒負向觀察窗。
    - 驗證：
      1. 語意：①以 Tab 鍵可到達編輯區內（前提）；②編輯區內容不變（未切換模式）；③編輯區不可編輯；④頁面持有之內容仍為 `RO` 原文；⑤頁面未收到回傳；⑥「復原」停用；⑦主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：編輯區內之按鍵於組件根之 capture 階段停止傳遞，不阻止瀏覽器預設行為（`guardLock`）。原測試：R15 唯讀時以 Tab 鍵移入編輯區再按鍵（三模式；原以程式聚焦起點，今改為點擊搜尋框）。

- **E2E-003**
  - title: 唯讀時滑鼠點擊核取方塊後按鍵回到頁面
  - description: 唯讀文件中以滑鼠左鍵或右鍵點擊待辦核取方塊，焦點不會留在編輯區內，因此之後按 Esc 等按鍵仍由頁面處理，例如關閉頁面上的對話框；頁面上方「最近按鍵：」會顯示 Escape。核取方塊的勾選狀態與文件內容都不變。適合唯讀文件嵌在對話框或含快捷鍵之頁面中。
  - flow:
    - 測試資料：文件 `RO`，唯讀。
    - 操作：開啟示範宿主頁 → 等載入完成 → 以左鍵點擊第一個核取方塊 → 等焦點離開編輯區 → 按 Esc → 以右鍵點擊同一核取方塊 → 等焦點離開編輯區 → 按 Esc → 依序按 Enter、Ctrl+Alt+2、Backspace、Delete、空白鍵、Z、切換編輯模式之快捷鍵、Tab → 經過 1 秒負向觀察窗。
    - 驗證：
      1. 語意：①每次點擊後焦點不在編輯區內；②兩次 Esc 皆由頁面收到，頁面收到之按鍵依序為 Escape、Escape，「最近按鍵：」顯示 Escape；③核取狀態不變；④編輯區內容不變；⑤編輯區不可編輯；⑥頁面持有之內容仍為 `RO` 原文；⑦頁面未收到回傳；⑧主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得與即時渲染；理由：分割預覽之編輯區為原始碼，無核取方塊。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：非鍵盤取得之焦點（不符 `:focus-visible`）由組件延後失焦（`releaseFocus`）；中鍵與拖曳之釋放另見 `spec/evidence/2026-10-04-probe13-Va-Vl.log` 之 Va。原測試：R15 唯讀時以滑鼠左鍵與右鍵點擊核取方塊（兩模式）。

- **E2E-004**
  - title: 唯讀時點擊連結另開分頁且按鍵回到頁面
  - description: 唯讀文件中的連結照常可點，點擊後另開分頁顯示連結內容；回到原頁後焦點不會留在編輯區內，按 Esc 仍由頁面處理，「最近按鍵：」顯示 Escape。點擊連結不改動文件。適合唯讀閱讀含參考連結之文件。
  - flow:
    - 測試資料：文件 `RO`（連結文字「連結」，網址 `/node_modules/vditor/package.json`），唯讀。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區內之「連結」 → 新分頁開啟 → 關閉新分頁 → 等焦點離開編輯區 → 按 Esc。
    - 驗證：
      1. 語意：①新分頁開啟且網址結尾為 `/node_modules/vditor/package.json`；②焦點不在編輯區內；③頁面收到之按鍵為 Escape；④頁面持有之內容仍為 `RO` 原文；⑤頁面未收到回傳；⑥主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得與即時渲染；理由：分割預覽之編輯區為原始碼，連結不可點（連結只在預覽區）。
    - 清理：關閉新分頁；瀏覽器每案全新。
    - 備註：所見即所得之連結為 `a` 元素，即時渲染為 `span.vditor-ir__link`，皆由 vditor 另開（`spec/evidence/2026-10-04-host-probe1.log` 之 P7）。原測試：R15 所見即所得唯讀時點擊連結（今擴為即時渲染）。

- **E2E-005**
  - title: 唯讀時以 Tab 鍵進入長文件捲動並一次離開
  - description: 唯讀文件內容超出編輯區高度時，可用 Tab 鍵把焦點移到編輯區本身，再按 PageDown 等鍵捲動閱讀；按 Shift+Tab 或 Tab 一次即可離開編輯區，焦點不會被拉回，也不會停在看不見的元素上。頁面在焦點進出編輯區時各收到一次聚焦與失焦通知。唯讀時不改動文件。適合以鍵盤閱讀長篇唯讀文件。
  - flow:
    - 測試資料：文件 `LONG`（標題＋30 段文字），唯讀，頁面記錄聚焦與失焦通知。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊搜尋框 → 連按 Tab 直到焦點位於編輯區本身 → 按 PageDown → 按 Shift+Tab → 按 Tab（回到編輯區本身）→ 按 Tab。
    - 驗證：
      1. 語意：①以 Tab 鍵可到達編輯區本身（前提）；②按 PageDown 後編輯區之捲動位置增加；③Shift+Tab 一次後焦點不在編輯區內；④再按 Tab 焦點回到編輯區本身；⑤再按 Tab 一次後焦點不在編輯區內，且不在頁面之隱藏 iframe 上；⑥頁面收到之通知依序為聚焦、失焦、聚焦、失焦；⑦頁面未收到回傳；⑧主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：唯讀已套用時編輯區本身之聚焦與失焦不交 vditor（其失焦處理會經 `getEditorRange` 拉回焦點），由組件代為通知；匯出用之隱藏 iframe 設 `tabindex=-1`（`removeExportPdf`）。原測試：R15 唯讀時以 Tab 鍵移入可捲動之編輯區本身（三模式）。

- **E2E-006**
  - title: 唯讀時焦點在編輯區，頁面快捷鍵可移走焦點
  - description: 焦點以 Tab 鍵停在唯讀編輯區時，按頁面提供的快捷鍵 Alt+F，焦點即移到頁面上方的搜尋框，不會被編輯器拉回。頁面以程式移動焦點的其他情形，例如對話框開啟時自動聚焦，也是如此。唯讀時不改動文件。適合頁面另有快捷鍵或自動聚焦行為的情境。
  - flow:
    - 測試資料：文件 `LONG`，唯讀。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊搜尋框 → 連按 Tab 直到焦點位於編輯區本身 → 按 Alt+F。
    - 驗證：
      1. 語意：①以 Tab 鍵可到達編輯區本身（前提）；②按 Alt+F 後焦點位於搜尋框；③主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：Alt+F 由頁面於 window 之 capture 階段處理並以程式聚焦搜尋框；組件之按鍵攔截在其後之組件根，capture 階段之頁面監聽照常收到（ADR-005）。原測試：R15 唯讀時焦點在編輯區本身、頁面以程式聚焦（三模式；原以程式呼叫 focus，今改為頁面快捷鍵）。

- **E2E-007**
  - title: 唯讀時選取文字仍通知頁面且按鍵不觸發按鍵通知
  - description: 唯讀文件仍可用滑鼠拖曳選取文字，例如供複製引用；選取時頁面會收到選取通知，點擊他處取消選取時收到取消選取通知。以 Tab 鍵把焦點移進唯讀編輯區後按 Esc、Ctrl+Enter 或一般字元，編輯器不會發出按鍵、Esc 與 Ctrl+Enter 通知，頁面不會因此執行編輯相關動作。唯讀時不改動文件。適合依選取內容顯示引用或註記功能的頁面。
  - flow:
    - 測試資料：文件 `LONG`，唯讀，頁面記錄選取、取消選取、按鍵、Esc、Ctrl+Enter 通知（`cbLog=1`）。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊搜尋框 → 連按 Tab 直到焦點位於編輯區本身 → 依序按 Esc、Ctrl+Enter、a → 經過 0.6 秒負向觀察窗 → 於編輯區以滑鼠自左上方拖曳至右下方選取文字 → 等頁面收到選取通知 → 點擊編輯區右上角空白處 → 等頁面收到取消選取通知。
    - 驗證：
      1. 語意：①以 Tab 鍵可到達編輯區本身（前提）；②按鍵後頁面未收到任何通知；③拖曳後頁面有選取之文字，且收到之通知依序為選取；④點擊他處後依序為選取、取消選取；⑤主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：按鍵於組件根 capture 階段停止傳遞，vditor 之按鍵處理（含 `settings.keydown`、`esc`、`ctrlEnter`）不執行；`selectstart` 不攔截，`settings.select`、`unSelect` 照常（JSDoc `editable`）。可編輯時之對照：同一按鍵序列會發出按鍵、Esc、Ctrl+Enter 通知（`spec/evidence/2026-10-04-host-probe4.log` 之 P17b）。新增案例（舊測試無）。探測：同檔 P17。

## 規則摘要

- 焦點語意同原生 readonly：鍵盤取得之焦點保留，非鍵盤取得之焦點延後釋放（ADR-005）。
- 焦點在唯讀編輯區內時，按鍵於組件根之 capture 階段停止傳遞，不阻止 Tab、捲動、開啟連結、複製等瀏覽器預設行為；頁面於 capture 階段之監聽仍收得到。
- 唯讀已套用時聚焦與失焦通知由組件代為發出且成對。
- 各案例過程中主控台不得出現錯誤。
- 視覺：本專案不建像素標準圖（ADR-007），各案例視覺項為「無」。

## 已知落差

- **焦點在唯讀編輯區內時按鍵不傳到頁面之一般按鍵處理（設計事實（記錄備查）；記於 2026-10-04）**：為使 vditor 之按鍵處理不改動唯讀內容，組件於組件根之 capture 階段停止傳遞（`guardLock`，JSDoc `editable` 已載明）。使用者可觀察之後果：以 Tab 鍵移入唯讀編輯區時，頁面以 bubble 階段註冊之快捷鍵（如 Esc 關閉對話框）收不到，需先移出編輯區；以 capture 階段註冊者不受影響。層級：組件設計取捨。
- **解除唯讀時鍵盤焦點停在核取方塊，之後輸入之文字落在核取方塊前（設計事實（記錄備查）；記於 2026-10-04）**：未曾鎖定時點擊核取方塊再輸入亦同（`spec/evidence/2026-10-04-probe11-T1-T2.log` 之 T1）。使用者可觀察之後果：解鎖後應先點擊要輸入之位置。層級：上游 vditor 既有行為。
