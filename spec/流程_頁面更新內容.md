# 流程_頁面更新內容

## 觸發

編輯器載入完成後，頁面可能再把新的內容交給編輯器，例如後端資料晚到、取得伺服器上的最新版本、恢復上一版、儲存後以伺服器回傳的內容寫回。編輯器據此判斷：等於自己最後回傳或目前顯示的內容時視為頁面寫回，不重載；否則以頁面的內容為準載入，使用者尚未編輯時新內容成為復原起點，已編輯時保留復原紀錄。本文件涵蓋這些更新與使用者輸入交錯時之表現。

- 入口：示範宿主頁（`spec/設計要點與取捨.md` 第二節），使用上方操作列「取得最新版本」「恢復上一版」與 Ctrl+S 儲存。
- 預設狀態：可編輯、文件 `ORI`、頁面同步回寫。

## 重要流程

- **E2E-001**
  - title: 尚未編輯時頁面送來資料且成為復原起點
  - description: 頁面先以空白開啟編輯器、稍後才取得文件資料時，資料送達後編輯器即顯示該內容；因為使用者尚未編輯，這份內容就是復原的起點，工具列的「復原 <Ctrl+Z>」按鈕維持停用，點擊也不會回到先前的空白，頁面不會收到變更。資料送達不需任何操作。適合先開啟編輯器、再非同步載入文件的頁面。
  - flow:
    - 測試資料：開啟時文件 `EMPTY`（空白），開頁後 2.5 秒送達 `NEW`（標題「新內容」、段落「非同步載入後之內容」）。
    - 操作：開啟示範宿主頁 → 等載入完成（編輯區空白）→ 等編輯區顯示新內容 → 點擊「復原 <Ctrl+Z>」。
    - 驗證：
      1. 語意：①資料送達當下編輯器已載入完成（前提），送達後編輯區顯示新內容，所見即所得為「新內容 非同步載入後之內容」，其他模式為「# 新內容 非同步載入後之內容」；②「復原」為停用；③點擊「復原」後仍為新內容，未回到空白；④頁面未收到回傳；⑤主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：`relaValue` 判定未編輯，以 `loadValue(true)` 清空復原紀錄。與 E2E-002 為未編輯與已編輯之對稱路徑；與 `流程_編輯器載入與關閉` 之載入中送達為同一時序之就緒後一側。原測試：R05（三模式）。

- **E2E-002**
  - title: 編輯後取得最新版本仍可復原至編輯內容
  - description: 使用者已在編輯區輸入內容後，於頁面上方操作列點擊「取得最新版本」，編輯器改為顯示伺服器上的最新版本；先前的編輯不會被清除，工具列的「復原 <Ctrl+Z>」按鈕維持可用，點擊一次即回到更新前自己編輯的內容。更新只改變編輯器顯示，是否以哪一份存回伺服器由頁面決定。適合他人更新後需比對或找回自己編輯內容的情境。
  - flow:
    - 測試資料：預設文件 `ORI`；「取得最新版本」第一次取得 `PULL1`（標題「外部」、段落「外部變更之內容」）。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後輸入 ZZZ → 等頁面收到結尾為 ZZZ 之回傳 → 停頓 0.6 秒 → 點擊「取得最新版本」 → 等編輯區顯示 `PULL1` → 停頓 0.6 秒 → 點擊「復原 <Ctrl+Z>」。
    - 驗證：
      1. 語意：①輸入後編輯區為開啟時內容接 ZZZ（前提）；②取得後編輯區顯示 `PULL1`，所見即所得為「外部 外部變更之內容」，其他模式為「# 外部 外部變更之內容」；③「復原」為可用；④復原後編輯區為開啟時內容接 ZZZ；⑤主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：`relaValue` 判定已編輯，以 `loadValue(false)` 保留復原紀錄。取得前之停頓使輸入寫入復原紀錄：分割預覽之回傳同步發出、寫入復原紀錄另於 100 毫秒後，期間載入新內容會清除尚未寫入者，與 E2E-005「未寫入復原紀錄之輸入不可復原」為同一行為。原測試：R11（三模式；原以程式改值，今改為點擊）。

- **E2E-003**
  - title: 恢復上一版時以頁面內容為準
  - description: 使用者先後輸入兩次、頁面各收到一次回傳後，於頁面上方操作列點擊「恢復上一版」，頁面把較早的那一版交給編輯器，編輯器即顯示該版本，畫面與頁面持有的內容一致，而不會因為與目前內容不同而被忽略。恢復只改變編輯器與頁面持有的內容，是否存回伺服器由頁面決定。適合提供版本紀錄或「上一步」功能的頁面。
  - flow:
    - 測試資料：預設文件 `ORI`，頁面同步回寫並記錄版本（開啟時內容與每次回傳）。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End → 以每鍵 250 毫秒輸入 ab → 等頁面收到 2 次回傳 → 點擊「恢復上一版」 → 等編輯區為開啟時內容接 a。
    - 驗證：
      1. 語意：①頁面收到 2 次回傳，分別結尾為 a 與 ab（前提）；②恢復後編輯區為開啟時內容接 a；③頁面持有之內容等於第一次回傳；④主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：恢復之值與最後回傳值、當前內容皆不同，非回寫，以頁面內容為準載入（ADR-003）。原測試：R13 父層設回先前之內容（三模式；原以程式改值，今改為點擊）。

- **E2E-004**
  - title: 儲存後伺服器回傳相同內容時游標位置不變
  - description: 開啟文件後把游標放在文件末尾、尚未輸入任何字時按 Ctrl+S 儲存，頁面上方顯示「上傳中…」，伺服器回傳的內容與原文相同只在結尾多一個換行；頁面以此寫回時編輯器視為相同內容而不重載，頁面顯示「已儲存」後接著輸入的字仍接在文件末尾。儲存結果以「已儲存」確認。適合儲存後以伺服器正規化結果寫回的頁面。
  - flow:
    - 測試資料：預設文件 `ORI`；儲存時伺服器於 0.3 秒後回傳上傳內容並於結尾補換行（`saveReply=echo&saveReplyAt=300`），上傳期間不鎖定。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End → 按 Ctrl+S → 等儲存狀態為「已儲存」 → 輸入 Y → 等頁面收到結尾為 Y 之回傳。
    - 驗證：
      1. 語意：①「已儲存」時頁面持有之內容為 `ORI` 原文接一個換行（前提：頁面已寫回）；②輸入後編輯區以開啟時內容開頭，其後為 Y；③頁面持有之內容與最後回傳一致；④主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：寫回時尚無回傳，`isEcho` 以當前內容比對（忽略結尾空白）而不重載；若重載，游標不保留，Y 不會接在末尾。原測試：R13 載入後尚未回拋時給予僅結尾換行不同之值（三模式；原以程式改值，今改為 Ctrl+S 儲存之伺服器回傳）。

- **E2E-005**
  - title: 輸入尚未回傳時取得最新版本
  - description: 使用者剛輸入一個字、編輯器還沒回傳給頁面時，就於頁面上方操作列點擊「取得最新版本」，編輯器改為顯示最新版本，剛輸入的字不會再回傳給頁面；因為已有編輯，「復原 <Ctrl+Z>」按鈕維持可用，點擊即回到編輯器最後記錄的內容。更新只改變編輯器顯示，是否存回伺服器由頁面決定。適合他人更新與自己輸入幾乎同時發生的情境。
  - flow:
    - 測試資料：預設文件 `ORI`，回傳防抖 600 毫秒（`hintTimeDetect=600`），頁面不回寫；「取得最新版本」第一次取得 `PULL1`。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後輸入 Z → 立即點擊「取得最新版本」 → 等編輯區顯示 `PULL1` → 經過 1.2 秒負向觀察窗 → 點擊「復原 <Ctrl+Z>」。
    - 驗證：
      1. 語意：①編輯區顯示 `PULL1`；②頁面未收到任何回傳，被取代之輸入不再回傳；③「復原」為可用；④復原後編輯區為開啟時內容；⑤主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得與即時渲染；理由：分割預覽每次輸入即同步回傳，沒有「已輸入而尚未回傳」之期間。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：`relaValue` 以編輯器內容與上次載入內容之差異判定已編輯；vditor 載入時清除待送之回傳計時器。Z 未經防抖寫入復原紀錄，故復原回到開啟時內容。原測試：R13 使用者已輸入而尚未回拋時父層改值（兩模式）。

- **E2E-006**
  - title: 輸入尚未回傳時連續取得兩個版本仍可復原
  - description: 使用者剛輸入一個字、尚未回傳時，連續兩次點擊「取得最新版本」，編輯器依序顯示兩個版本，最後顯示較新的那一版；「復原 <Ctrl+Z>」按鈕維持可用，點擊一次即回到前一個版本。更新只改變編輯器顯示，是否存回伺服器由頁面決定。適合伺服器版本頻繁更新的情境。
  - flow:
    - 測試資料：同 E2E-005；「取得最新版本」依序取得 `PULL1`、`PULL2`（標題「E2」、段落「第二次外部」）。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後輸入 Z → 立即點擊「取得最新版本」 → 等編輯區顯示 `PULL1` → 等待 1.2 秒使載入之內容寫入復原紀錄 → 再點擊「取得最新版本」 → 等編輯區顯示 `PULL2` → 經過 1.2 秒觀察窗 → 點擊「復原 <Ctrl+Z>」。
    - 驗證：
      1. 語意：①編輯區顯示 `PULL1`（前提）；②再次取得後顯示 `PULL2`；③「復原」為可用；④復原後編輯區顯示 `PULL1`；⑤主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得與即時渲染；理由同 E2E-005。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：保留復原紀錄之載入使已編輯狀態延續到之後之載入（`loadValue` 設定 `editedAfterLoad`）。兩次取得之間之等待涵蓋 600 毫秒防抖之復原紀錄寫入，無使用者可觀察之訊號，故為固定等待。原測試：R13 連續改值兩次（兩模式）。

- **E2E-007**
  - title: 儲存回應晚到時繼續輸入不受影響
  - description: 使用者輸入並已回傳給頁面後按 Ctrl+S 儲存，在伺服器回應前繼續輸入下一個字；伺服器回應時頁面以上傳時的內容寫回，編輯器判斷那是自己先前回傳的內容而不重載，剛輸入的字仍保留，接著輸入的字接在末尾。儲存結果以頁面上方的「已儲存」確認。適合儲存期間不鎖定編輯、回應較慢的頁面。
  - flow:
    - 測試資料：預設文件 `ORI`，回傳防抖 600 毫秒，頁面同步回寫；儲存時伺服器於 0.3 秒後回傳上傳內容並於結尾補換行，上傳期間不鎖定。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後輸入 a → 等頁面收到結尾為 a 之回傳 → 按 Ctrl+S → 輸入 b → 等儲存狀態為「已儲存」 → 輸入 c → 等頁面收到結尾為 abc 之回傳。
    - 驗證：
      1. 語意：①「已儲存」時頁面只收到 1 次回傳且頁面持有之內容為該回傳接一個換行（前提：寫回發生在 b 回傳之前）；②此時編輯區為開啟時內容接 ab；③輸入 c 後編輯區為開啟時內容接 abc；④主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得與即時渲染；理由同 E2E-005。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：寫回之值等於最後回傳值（忽略結尾空白），`isEcho` 第一分支。寫回若為更早之舊值則以舊值載入（〈已知落差〉）。原測試：R13 父層回寫最後回拋值而使用者已再輸入（兩模式；原以程式改值，今改為儲存之伺服器回傳）。

- **E2E-008**
  - title: 分割預覽下頁面修整開頭空白時以頁面內容為準
  - description: 在分割預覽模式於文件開頭輸入空白，頁面把收到的內容去除前後空白後寫回；開頭空白的增減屬於內容變更，編輯器以頁面的內容為準重新載入，畫面與頁面持有的內容一致，不會留下頁面已去除的空白。適合儲存前會修整空白的頁面。
  - flow:
    - 測試資料：預設文件 `ORI`，分割預覽，頁面修整兩端空白後寫回（`writeMode=trim`）。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區 → 按 Ctrl+Home → 輸入一個空白 → 等頁面收到回傳。
    - 驗證：
      1. 語意：①頁面收到之第一筆回傳以空白開頭（前提）；②頁面持有之內容等於最後回傳去除兩端空白；③編輯區顯示「# 標題 第一段內容abc 第二段內容xyz」，且編輯區原始文字（不正規化空白）以「#」開頭、開頭無空白；④主控台無錯誤。
      2. 視覺：無。
    - 模式：只測分割預覽；理由：所見即所得與即時渲染之回傳不會以空白開頭，開頭輸入之空白於重繪時即被去除，修整開頭之情境不發生（`spec/evidence/2026-10-04-probe9-B14-D3.log` 之 B14）。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：回寫判斷只忽略結尾空白，開頭空白之增減視為內容變更（`normEcho`）。原測試：R13 sv 模式父層修整開頭空白。

    - 驗證：
      1. 語意：①輸入後編輯區為開啟時內容接 abc；②取得後編輯區顯示 `PULL1`；③主控台無錯誤。

- **E2E-010**
  - title: 伺服器以 CRLF 換行回傳相同內容時游標不變

    - 驗證：

      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：回寫判斷將 `\r\n` 正規化為 `\n`（`normEcho`）。與 E2E-004 為同一回寫分支之換行符變體。新增案例（舊測試無）。探測：`spec/evidence/2026-10-04-host-probe4.log` 之 P20。

## 測試資料

| 變體 | 具名對象 | 取用方式 | 選它的理由 |
|---|---|---|---|
| 晚到之資料 | `EMPTY` → `NEW` | `doc=EMPTY&dataAt=2500&dataDoc=NEW` | 空白與有內容一眼可分，可驗證復原不回到空白 |
| 伺服器版本 | `PULL1`、`PULL2` | 「取得最新版本」 | 與 `ORI` 內容完全不同 |
| 伺服器回傳 | 上傳內容接換行 | `saveReply=echo` | 回寫判斷之「等於當前內容」與「等於最後回傳」兩分支 |
| 頁面回寫方式 | `sync`、`none`、`trim` | `writeMode` | 回寫與不回寫兩類，修整開頭空白一類 |

## 規則摘要

- 回寫判斷：等於最後回傳值或當前內容（忽略結尾空白與換行符）不重載；其他以頁面內容為準載入；未編輯時清空復原紀錄、已編輯時保留（ADR-003）。
- 載入新內容時若編輯區持有焦點，游標不保留（JSDoc `value`）。
- 延遲或亂序回寫之協調屬頁面（裁決紀錄 2026-10-04），不設「延遲回寫不掉字」之案例。
- 各案例過程中主控台不得出現錯誤。
- 視覺：本專案不建像素標準圖（ADR-007），各案例視覺項為「無」。

## 已知落差

- **頁面延遲回寫較早之回傳時，以該舊值載入而使之後之輸入錯置（設計事實（記錄備查）；裁決 2026-10-04）**：頁面每筆回傳延後 1 秒才寫回時，以每鍵 400 毫秒輸入 abcd，最終編輯區為開頭多一個 d、末尾只剩 a（三模式皆同，`spec/evidence/2026-10-04-host-probe3.log` 之 P9）；Vue 原生輸入框、CKEditor、TinyMCE、Quill 之官方封裝在同條件下亦遺失或錯置輸入（`spec/evidence/2026-10-04-cmp-writeback.log`，該檔 vditor 一列為第二輪舊版元件之結果，不代表現行）。使用者可觀察之後果：頁面若延後寫回，快速輸入時文字會錯位。層級：頁面責任（ADR-001）；頁面應同步寫回，或於延遲期間自行協調。
- **載入新內容時游標不保留（設計事實（記錄備查）；記於 2026-10-04）**：以頁面內容為準載入時整份內容被取代，與 CKEditor 等官方封裝相同（`spec/設計要點與取捨.md` ADR-003；JSDoc `value`）。使用者可觀察之後果：取得最新版本後須重新點擊要編輯的位置。層級：組件設計。
