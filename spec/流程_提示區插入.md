# 流程_提示區插入

## 觸發

頁面可為編輯器設定觸發字串（例如「/ht」或「@」），使用者在行首或空白之後輸入觸發字串，停頓片刻後編輯器在游標附近顯示頁面提供的提示區；點選提示區中的項目，編輯器移除游標前剛輸入的觸發字串，於該處插入項目內容。本文件涵蓋插入之位置與回傳、提示區開啟中頁面更新內容或鎖定時之處理，以及提示區外層 state 屬性隨開啟與關閉之轉換。提示區僅在所見即所得與即時渲染模式提供，分割預覽不支援（vditor 4.0.0 起停用）。

- 入口：示範宿主頁（`spec/設計要點與取捨.md` 第二節），以 `keyHint` 設定觸發字串；提示區內容由頁面提供，示範頁為一個「插入XYZ」按鈕，點擊後插入 XYZ 並關閉提示區。
- 預設狀態：可編輯、文件 `ORI`、頁面同步回寫、回傳防抖 100 毫秒。

## 重要流程

- **E2E-001**
  - title: 點選提示項目插入內容（以「/ht」為例）
  - description: 在編輯區文件末尾先輸入一個空白再輸入觸發字串「/ht」，停頓片刻後編輯區附近出現頁面提供的提示區；點擊其中的「插入XYZ」，編輯器移除剛輸入的「/ht」，在原處插入 XYZ，提示區隨即關閉，頁面只收到一次插入後的內容。插入後「復原 <Ctrl+Z>」維持可用，接著輸入的字接在 XYZ 之後。插入只回傳給頁面，是否存回伺服器由頁面決定；觸發字串須位於行首或空白之後，否則不出現提示區。適合以關鍵字快速插入範本、連結或人名。
  - flow:
    - 測試資料：預設文件 `ORI`，觸發字串「/ht」（`keyHint=/ht`），頁面同步回寫。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後輸入「 /ht」 → 等頁面收到結尾為「/ht」之回傳 → 等提示區出現「插入XYZ」 → 點擊「插入XYZ」 → 等頁面收到含 XYZ 之回傳 → 經過 1.5 秒負向觀察窗 → 以每鍵 150 毫秒輸入 QQ → 等頁面收到含 XYZQQ 之回傳。
    - 驗證：
      1. 語意：①插入後編輯區含 XYZ 且不含「/ht」；②點擊後頁面恰收到 1 次回傳，且該回傳不含「/ht」；③頁面持有之內容等於該回傳；④提示區已關閉；⑤「復原」為可用（插入未被當成頁面更新而清空復原紀錄）；⑥輸入 QQ 後編輯區含 XYZQQ；⑦編輯區仍以文件開頭之標題開頭；⑧主控台無錯誤。
      2. 視覺：無。
    - 模式：所見即所得與即時渲染各一輪；分割預覽不支援提示區（vditor 4.0.0 起停用，見 E2E-009 與〈已知落差〉）。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：提示區偵測由回傳驅動，於回傳後每 50 毫秒輪詢 vditor 之提示元素（`detectAndShowHint`、`findAnchor`）；插入以 vditor 公開之 `insertValue` 進行並經正常輸入流程回傳（ADR-006）。觀察窗 1.5 秒涵蓋偵測輪詢與防抖，以確認不會再有第二次回傳。觸發字串須在行首或空白之後由 vditor 判定（`node_modules/vditor/src/ts/hint/index.ts` 之 `getKey`）。輸入途中若有一次中間回傳（如「 /h」），其偵測輪詢在最後一字輸入後即找到 vditor 同步渲染之提示錨點，提示區可能早於最後一次回傳出現，故先等觸發字串之回傳再等提示區（2026-10-04 實測）。原測試：R09 提示區插入（原三模式；2026-11-09 起分割預覽不支援提示區，見 E2E-009）。

- **E2E-002**
  - title: 中段觸發時只移除本次觸發字串（以「@」為例）
  - description: 觸發字串若也出現在文件其他地方，例如後文有電子郵件地址「a@b.com」，在中段某一行末尾輸入空白與「@」叫出提示區並點擊「插入XYZ」時，編輯器只移除游標前剛輸入的「@」，在該處插入 XYZ，後文的「a@b.com」保持不變，接著輸入的字也接在 XYZ 之後。插入只回傳給頁面，是否存回伺服器由頁面決定。適合文件中已有觸發字元時仍要插入內容的情境。
  - flow:
    - 測試資料：文件 `MAIL`（標題、段落「第一段內容」、段落「聯絡a@b.com」），觸發字串「@」，頁面同步回寫。
    - 操作：開啟示範宿主頁 → 等載入完成 → 將游標移到「第一段內容」行末（點擊該段後按 End）→ 以每鍵 150 毫秒輸入「 @」 → 等頁面收到含「第一段內容 @」之回傳 → 等提示區出現 → 點擊「插入XYZ」 → 等頁面收到含 XYZ 之回傳 → 以每鍵 150 毫秒輸入 QQ → 等頁面收到含 XYZQQ 之回傳。
    - 驗證：
      1. 語意：①編輯區含「第一段內容 XYZQQ」；②編輯區仍含「a@b.com」；③頁面持有之內容含「a@b.com」且不含「 @XYZ」；④頁面持有之內容與最後回傳一致；⑤主控台無錯誤。
      2. 視覺：無。
    - 模式：所見即所得與即時渲染各一輪；分割預覽不支援提示區（vditor 4.0.0 起停用，見 E2E-009 與〈已知落差〉）。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：只檢查游標前緊鄰之文字，不以全文搜尋（`removeHintTrigger`）。原測試：R09 於文件中段觸發且後文含相同字串（原三模式；2026-11-09 起分割預覽不支援提示區，原「分割預覽以鍵盤移至第 3 行」之輪次移除）。

- **E2E-003**
  - title: 提示區開啟中伺服器回傳新內容時提示區關閉
  - description: 提示區開啟時按 Ctrl+S 儲存，伺服器回傳與目前不同的內容並由頁面寫回時，編輯器以伺服器的內容為準重新載入，原本開啟的提示區隨即關閉，避免插入到已被取代的位置；載入新內容不會回傳給頁面。儲存結果以頁面上方的「已儲存」確認，若仍需插入，請在新內容中重新輸入觸發字串。適合儲存後由伺服器整理內容的頁面。
  - flow:
    - 測試資料：預設文件 `ORI`，觸發字串「/ht」；儲存時伺服器於 0.3 秒後回傳 `SERVER`，上傳期間不鎖定。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後以每鍵 150 毫秒輸入「 /ht」 → 等頁面收到結尾為「/ht」之回傳 → 等提示區出現 → 按 Ctrl+S → 等儲存狀態為「已儲存」 → 經過 0.6 秒負向觀察窗。
    - 驗證：
      1. 語意：①提示區已關閉，且提示區外層 state 屬性為 hidden；②編輯區顯示 `SERVER`，所見即所得為「標題 第一段內容abc 伺服器回傳之內容」，即時渲染前加「# 」；③提示區出現後頁面未再收到回傳；④主控台無錯誤。
      2. 視覺：無。
    - 模式：所見即所得與即時渲染各一輪；分割預覽不支援提示區（vditor 4.0.0 起停用，見 E2E-009 與〈已知落差〉）。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：以鍵盤觸發儲存，因提示區以點擊外部關閉，若以點擊頁面按鈕觸發更新將無法分辨關閉原因（`spec/evidence/2026-10-04-host-probe1.log` 之 P6：Ctrl+S 與游標移動不關閉、點擊外部關閉）。整份內容被取代時組件先關閉提示區（`relaValue` 之 `hideHint`）。原測試：R09/R13 提示區開啟中父層載入新內容（三模式；原以程式改值，今改為儲存之伺服器回傳）。

- **E2E-004**
  - title: 提示區開啟中儲存鎖定時提示區關閉
  - description: 提示區開啟時按 Ctrl+S 儲存，頁面於上傳期間把編輯器設為唯讀，提示區隨即關閉，唯讀期間無法再經提示區插入，文件內容維持輸入觸發字串時的樣子，頁面不會收到變更，「復原 <Ctrl+Z>」停用。上傳完成、頁面顯示「已儲存」後恢復可編輯，可重新輸入觸發字串。適合儲存期間鎖定編輯的頁面。
  - flow:
    - 測試資料：預設文件 `ORI`，觸發字串「/ht」；儲存時上傳期間唯讀 3 秒，伺服器不寫回。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後以每鍵 150 毫秒輸入「 /ht」 → 等頁面收到結尾為「/ht」之回傳 → 等提示區出現 → 按 Ctrl+S → 等編輯區不可編輯 → 經過 0.6 秒負向觀察窗。
    - 驗證：
      1. 語意：①提示區已關閉，且提示區外層 state 屬性為 hidden；②編輯區結尾仍為「/ht」；③提示區出現後頁面未再收到回傳；④「復原」停用；⑤主控台無錯誤。
      2. 視覺：無。
    - 模式：所見即所得與即時渲染各一輪；分割預覽不支援提示區（vditor 4.0.0 起停用，見 E2E-009 與〈已知落差〉）。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：鎖定分支關閉提示區（`applyEditable` 之 `hideHint`）；唯讀時之插入請求一律不插入並關閉（`insertValue`）。原測試：R15 提示區開啟中鎖定（三模式；原以程式鎖定，今改為 Ctrl+S 儲存）。

- **E2E-005**
  - title: 註冊多組觸發字串時依輸入者顯示提示區
  - description: 頁面可同時設定多組觸發字串，例如「/ht」與「/kw」；在文件末尾輸入空白與「/kw」後，提示區出現並標示目前觸發的是「/kw」，點擊「插入XYZ」後編輯器移除剛輸入的「/kw」並插入 XYZ。插入只回傳給頁面，是否存回伺服器由頁面決定。適合一個編輯器提供多種插入功能，例如範本與關鍵字。
  - flow:
    - 測試資料：預設文件 `ORI`，觸發字串「/ht」與「/kw」（`keyHint=/ht,/kw`），提示區顯示目前之觸發字串。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後輸入「 /kw」 → 等頁面收到結尾為「/kw」之回傳 → 等提示區出現 → 點擊「插入XYZ」 → 等頁面收到含 XYZ 之回傳。
    - 驗證：
      1. 語意：①提示區標示之觸發字串為「/kw」；②插入後編輯區含 XYZ 且不含「/kw」；③主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得；理由：觸發字串之判定由 vditor 提示模組處理（`hint/index.ts` 之 `getKey`），與模式無關，兩模式之插入由 E2E-001 涵蓋。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：觸發字串陣列由 `keyHints` 轉為 vditor 之提示擴充，提示區之 `hint` 為目前觸發字串（slot props）。新增案例（舊測試無）。探測：`spec/evidence/2026-10-04-host-probe4.log` 之 P21。

- **E2E-006**
  - title: 觸發字串前非空白時不出現提示區
  - description: 觸發字串必須位於行首或空白之後才會叫出提示區；若直接接在文字後面，例如輸入「a/ht」，提示區不會出現，輸入的文字照常保留並回傳給頁面。需要提示區時，請先輸入空白再輸入觸發字串。適合內容中本來就會出現斜線等字元的文件，避免誤觸。
  - flow:
    - 測試資料：預設文件 `ORI`，觸發字串「/ht」。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後輸入「a/ht」 → 等頁面收到結尾為「a/ht」之回傳 → 經過 1.5 秒負向觀察窗。
    - 驗證：
      1. 語意：①提示區未出現；②編輯區結尾為「a/ht」；③主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得；理由同 E2E-005。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：vditor `getKey` 要求觸發字串在行首或其前一字元為空白。與 E2E-001 為出現與不出現之對稱路徑。新增案例（舊測試無）。探測：`spec/evidence/2026-10-04-host-probe4.log` 之 P22。

- **E2E-007**
  - title: 提示區開啟與關閉時狀態依序轉換（以「/ht」為例）
  - description: 頁面為編輯器設定觸發字串「/ht」時，編輯器載入完成後提示區尚未顯示。使用者在文件末尾輸入一個空白與「/ht」，停頓片刻後提示區在游標附近淡入出現，約 0.2 秒後位置與透明度不再變動，即可點選其中的「插入XYZ」，點選後提示區隨即關閉。提示區外層帶有 state 屬性，供頁面判斷提示區是否已靜止：未顯示時為 hidden，淡入期間為 opening，靜止後為 opened，關閉後回到 hidden，不會出現其他值。state 屬性只反映提示區的顯示過程，不影響插入與回傳；插入的內容只回傳給頁面，是否存回伺服器由頁面決定。適合頁面或自動化測試需等提示區靜止後再操作的情境。
  - flow:
    - 測試資料：預設文件 `ORI`，觸發字串「/ht」（`keyHint=/ht`），頁面同步回寫。
    - 操作：開啟示範宿主頁 → 等載入完成 → 讀取提示區外層 state 屬性與提示區是否可見 → 安裝 state 屬性變化記錄器 → 點擊編輯區、按 Ctrl+End 後輸入「 /ht」 → 等頁面收到結尾為「/ht」之回傳 → 等 state 屬性成為 opened → 讀取「插入XYZ」是否可見 → 點擊「插入XYZ」 → 等頁面收到含 XYZ 之回傳 → 等 state 屬性成為 hidden → 經過 0.6 秒負向觀察窗 → 取出記錄器之序列。
    - 驗證：
      1. 語意：①載入完成、輸入前，提示區外層 state 屬性為 hidden、提示區不可見，且組件已建立提示區控制器（實例之 `bp` 非空）；②記錄器所見之 state 變化序列（相鄰重複去除）恰為 opening、opened、hidden，不含 hiding 或其他值；③state 為 opened 時「插入XYZ」可見；④點擊後 state 為 hidden、「插入XYZ」不可見，編輯區含 XYZ 且不含「/ht」；⑤主控台無錯誤（含組件掛載時不拋錯）。
      2. 視覺：無。
    - 模式：所見即所得與即時渲染各一輪；分割預覽不支援提示區（vditor 4.0.0 起停用，見 E2E-009 與〈已知落差〉）。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：state 由 w-component-vue 之 `buildPopper` 寫入（`src/js/buildPopper.mjs` 之 `ts.begin('opening','opened',transitionTime)` 與 `ts.stop('hidden')`），值域依 `createTransitionState` 與 `WTooltip.vue` JSDoc 為 hidden、opening、opened，關閉無過場、不使用 hiding（2026-11-01 讀 w-component-vue 2.5.35 原始碼）。w-component-vue 2.5.35 起 `buildPopper` 要求呼叫端 vo 預先宣告 state，缺少時於 mounted 拋 `invalid vo.state`、`bp` 為空、提示區不出現（Gitea #36）；修前重現與修後取樣見 `spec/evidence/2026-11-01-vd36-pre-fix.json`、`2026-11-01-vd36-post-fix.json`。記錄器為 MutationObserver 只讀記錄 state 屬性；`bp` 為內部欄位之只讀白箱觀察，使用者可觀察之等價結果為提示區能否出現（E2E-001）。新增案例。

- **E2E-008**
  - title: 未設定觸發字串時不出現提示區
  - description: 頁面沒有為編輯器設定觸發字串時，編輯器照常載入與編輯，輸入「/ht」只是一般文字，提示區不會出現，其外層的 state 屬性維持 hidden，輸入的文字照常保留並回傳給頁面。需要提示區時，請由頁面設定觸發字串。適合不需要提示區的頁面確認編輯器不受提示區機制影響。
  - flow:
    - 測試資料：預設文件 `ORI`，不設觸發字串（無 `keyHint` 參數），頁面同步回寫。
    - 操作：開啟示範宿主頁 → 等載入完成 → 安裝 state 屬性變化記錄器 → 點擊編輯區、按 Ctrl+End 後輸入「 /ht」 → 等頁面收到結尾為「/ht」之回傳 → 經過 1.5 秒負向觀察窗 → 讀取 state 屬性與提示區是否可見 → 取出記錄器之序列。
    - 驗證：
      1. 語意：①「插入XYZ」不可見；②state 屬性為 hidden，記錄器序列為空（未曾變化）；③編輯區結尾為「/ht」；④主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得；理由：提示區控制器與模式無關，兩模式之提示區出現與 state 轉換由 E2E-007 涵蓋。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：提示區控制器於組件掛載時一律建立，與是否設觸發字串無關（`WVditorVue.vue` 之 `mounted`），故缺 state 宣告時未設觸發字串者同樣於掛載時拋錯；與 E2E-007 為設與不設觸發字串之對稱路徑。觀察窗 1.5 秒涵蓋提示偵測輪詢（50 毫秒）與回傳防抖。新增案例。

- **E2E-009**
  - title: 分割預覽下輸入觸發字串不出現提示區
  - description: 頁面為編輯器設定觸發字串「/ht」，但編輯模式為分割預覽時，編輯器不提供提示區：在文件末尾輸入一個空白與「/ht」，停頓片刻後提示區不會出現，其外層的 state 屬性維持 hidden，輸入的文字照常保留並即時回傳給頁面。需要提示區時，請使用所見即所得或即時渲染模式。適合確認頁面在分割預覽模式不會因設定觸發字串而出現異常。
  - flow:
    - 測試資料：預設文件 `ORI`，觸發字串「/ht」（`keyHint=/ht`），`mode=sv`，頁面同步回寫。

      1. 語意：①「插入XYZ」不可見；②state 屬性為 hidden，記錄器序列為空（未曾變化）；③編輯區結尾為「/ht」；④主控台無錯誤；前提：載入完成後 state 為 hidden。
      2. 視覺：無。
    - 模式：只測分割預覽；理由：此案為「分割預覽不支援提示區」之守護，其他兩模式之提示區由 E2E-001～007 涵蓋。

## 測試資料

| 變體 | 具名對象 | 取用方式 | 選它的理由 |
|---|---|---|---|
| 觸發字串 | 「/ht」、「@」 | `keyHint` | 多字元與單字元兩類；「@」與文件中電子郵件同字元 |
| 多組觸發字串 | 「/ht」與「/kw」 | `keyHint=/ht,/kw` | 驗證以實際輸入者判定 |
| 未設觸發字串 | 無 | 不帶 `keyHint` 參數 | 提示區機制不啟用時之對稱路徑（E2E-008） |
| 插入位置 | 文件末尾、文件中段 | `ORI`、`MAIL` | 中段且後文含相同字元為最易誤刪之情境 |
| 編輯模式 | 所見即所得、即時渲染、分割預覽 | `mode` | 前兩者支援提示區（E2E-001～008），分割預覽不支援（E2E-009） |
| 提示區開啟中之頁面動作 | 伺服器回傳新內容、儲存鎖定 | `saveReply=server`、`saveLock` | 整份取代與唯讀兩類 |

## 規則摘要

- 提示區於回傳後偵測，與回傳共用防抖時間（預設 100 毫秒）；提示區顯示時編輯區失焦，避免使用者以鍵盤繼續改動。
- 分割預覽不支援提示區（vditor 4.0.0 起停用，E2E-009、〈已知落差〉）；該模式下設定觸發字串無作用、輸入照常回傳。
- 插入時只移除游標前本次輸入之觸發字串，游標已移離觸發字串時只插入（ADR-006）。「游標已移離」之分支不設案例：提示區開啟時編輯區已失焦、點擊編輯區即關閉提示區，使用者操作造不出「提示區開啟中而游標已移開」之狀態，屬防禦性分支（`removeHintTrigger`）。
- 整份內容被取代、或編輯器被設為唯讀時，提示區先關閉；唯讀或未就緒時之插入請求不插入。
- 提示區以點擊外部關閉，鍵盤不關閉。
- 提示區外層 state 屬性之值域為 hidden、opening、opened（淡入約 0.2 秒，以內層內容自身之過場結束落定，事件未觸發時逾時後備落定）；關閉無過場，由 opened（開啟中途關閉則由 opening）直接成為 hidden。組件 data 須預先宣告 state：w-component-vue 2.5.35 起 `buildPopper` 檢查呼叫端 vo 之必備鍵，缺 state 即於掛載時拋 `invalid vo.state`（未設觸發字串者亦然）；本組件相依 `w-component-vue ^2.5.35`（`spec/設計要點與取捨.md` 〈上游套件事項之歸屬〉）。
- 各案例過程中主控台不得出現錯誤。
- 視覺：本專案不建像素標準圖（ADR-007），各案例視覺項為「無」。

## 已知落差

本流程目前無未修復之缺陷（2026-11-09）。插入內容以 HTML 片段插入、含不可信資料時須由頁面跳脫，屬 JSDoc 已載明之使用界定，不另列。

- **分割預覽不支援提示區（設計事實（記錄備查）；記於 2026-11-09）**：vditor 4.0.0 起分割預覽之提示一律停用（`node_modules/vditor/src/ts/hint/index.ts:26-29`、`:133-137`；3.11.3 之 `render` 無此檢查，分割預覽之提示以 `insertHTML` 插入），其編輯區改為 textarea（`src/ts/sv/index.ts:13`），無游標位置可供定位提示區。使用者可觀察之後果：頁面在分割預覽模式設定 `keyHint` 無作用，輸入觸發字串只是一般文字；所見即所得與即時渲染不變。層級：上游 vditor 之模式行為，組件照實轉交並於 JSDoc、README 載明。原載「分割預覽支援提示區（原 E2E-001～004、007 之分割預覽輪）」自 vditor 4.0.1 起不成立：升版後該 5 案之分割預覽輪紅（提示區不出現，`spec/evidence/2026-11-09-vd01-upgrade-4.0.1.md` 之第 2 節），已移除並新增 E2E-009 守護。組件自行於分割預覽實作提示區（偵測觸發字串、以 textarea 選取範圍定位與插入）不在本輪範圍，是否需要待使用端需求再議。

- **（已於 2026-11-01 修復）組件未宣告 state，w-component-vue 2.5.35 起掛載時拋 `invalid vo.state`，提示區失效**（分類：缺陷，已修復；層級：本套件產品碼；Gitea #36，使用端提出）
  - 症狀：以原始碼引用組件（`w-vditor-vue/src/components/WVditorVue.vue`）且安裝 w-component-vue 2.5.35 者，每個組件實例於掛載時拋 `Error: invalid vo.state`（`mounted` 內 `new BuildPopper(vo, …)`，修前 `WVditorVue.vue:434`），實例之 `bp` 為 null，設 keyHint 者輸入「/ht」後提示區不出現，畫面無提示、僅主控台出現錯誤；未設 keyHint 者亦拋同一錯誤（`bp` 於掛載時一律建立）。以 `dist` 引用者不受影響（`dist` 內嵌打包當時之 `buildPopper`）。
  - 成因：`w-component-vue` 2.5.35 之 `src/js/buildPopper.mjs:23-41` 把 state 加入呼叫端 vo 必備鍵（`:35`），缺少即拋錯（該檔 `:62-72` 以過場追蹤器寫入 `vo.state`）；本組件 data 未宣告。w-component-vue 端不放寬檢查（主控裁定，依使用者原則：自有套件不做向下相容補丁，由下游配合）。
  - 修前重現（2026-11-01）：安裝 2.5.35 後以現行原始碼編譯，`e2e-key-hint` 14 案全紅（`Error: invalid vo.state`）；探測 `spec/evidence/2026-11-01-vd36-pre-fix.json`（console 為 `Error: invalid vo.state`，`bpIsNull` 為 true，`hintShown` 為 false）。
  - 修復紀錄：`WVditorVue.vue` data 宣告 `state: 'hidden'`（`:338`）、提示區外層 `.WPopperFix` 綁定 `:state="state"`（`:19`，寫法比照 `WTooltip.vue`）、JSDoc 補 state 值與時機；`package.json` 相依 `w-component-vue` 改 `^2.5.35`。修後取樣 `spec/evidence/2026-11-01-vd36-post-fix.json`：掛載無錯誤、`bp` 已建立、state 序列 hidden、opening、opened、hidden。受影響案例：E2E-001～006 修前全紅（主控台錯誤與提示區不出現）、修後全綠；新增 E2E-007（state 轉換）、E2E-008（未設觸發字串），E2E-003／004 補 state 斷言。`dist` 已以現行原始碼重建並以 `E2E_DIST_DIR=dist` 跑同一組案例。
