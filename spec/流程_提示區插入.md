# 流程_提示區插入

## 觸發

頁面可為編輯器設定觸發字串（例如「/ht」或「@」），使用者在行首或空白之後輸入觸發字串，停頓片刻後編輯器在游標附近顯示頁面提供的提示區；點選提示區中的項目，編輯器移除游標前剛輸入的觸發字串，於該處插入項目內容。本文件涵蓋插入之位置與回傳、提示區開啟中頁面更新內容或鎖定時之處理。

- 入口：示範宿主頁（`spec/設計要點與取捨.md` 第二節），以 `keyHint` 設定觸發字串；提示區內容由頁面提供，示範頁為一個「插入XYZ」按鈕，點擊後插入 XYZ 並關閉提示區。
- 預設狀態：可編輯、文件 `ORI`、頁面同步回寫、回傳防抖 100 毫秒。

## 重要流程

- **E2E-001**
  - title: 點選提示項目插入內容（以「/ht」為例）
  - description: 在編輯區文件末尾先輸入一個空白再輸入觸發字串「/ht」，停頓片刻後編輯區附近出現頁面提供的提示區；點擊其中的「插入XYZ」，編輯器移除剛輸入的「/ht」，在原處插入 XYZ，提示區隨即關閉，頁面只收到一次插入後的內容。插入後「復原 <Ctrl+Z>」維持可用，接著輸入的字接在 XYZ 之後。插入只回傳給頁面，是否存回伺服器由頁面決定；觸發字串須位於行首或空白之後，否則不出現提示區。適合以關鍵字快速插入範本、連結或人名。
  - flow:
    - 測試資料：預設文件 `ORI`，觸發字串「/ht」（`keyHint=/ht`），頁面同步回寫。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後輸入「 /ht」 → 等頁面收到結尾為「/ht」之回傳 → 等提示區出現「插入XYZ」 → 點擊「插入XYZ」 → 等頁面收到含 XYZ 之回傳 → 經過 1.5 秒負向觀察窗 → 以每鍵 150 毫秒輸入 QQ → 等頁面收到含 XYZQQ 之回傳。
    - 驗證：
      1. 語意：①插入後編輯區含 XYZ 且不含「/ht」；②點擊後頁面恰收到 1 次回傳，且該回傳不含「/ht」；③頁面持有之內容等於該回傳；④提示區已關閉；⑤「復原」為可用（插入未被當成頁面更新而清空復原紀錄）；⑥輸入 QQ 後編輯區含 XYZQQ；⑦編輯區仍以文件開頭之標題開頭；⑧主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：提示區偵測由回傳驅動，於回傳後每 50 毫秒輪詢 vditor 之提示元素（`detectAndShowHint`、`findAnchor`）；插入以 vditor 公開之 `insertValue` 進行並經正常輸入流程回傳（ADR-006）。觀察窗 1.5 秒涵蓋偵測輪詢與防抖，以確認不會再有第二次回傳。觸發字串須在行首或空白之後由 vditor 判定（`node_modules/vditor/src/ts/hint/index.ts` 之 `getKey`）。輸入途中若有一次中間回傳（如「 /h」），其偵測輪詢在最後一字輸入後即找到 vditor 同步渲染之提示錨點，提示區可能早於最後一次回傳出現，故先等觸發字串之回傳再等提示區（2026-10-04 實測）。原測試：R09 提示區插入（三模式）。

- **E2E-002**
  - title: 中段觸發時只移除本次觸發字串（以「@」為例）
  - description: 觸發字串若也出現在文件其他地方，例如後文有電子郵件地址「a@b.com」，在中段某一行末尾輸入空白與「@」叫出提示區並點擊「插入XYZ」時，編輯器只移除游標前剛輸入的「@」，在該處插入 XYZ，後文的「a@b.com」保持不變，接著輸入的字也接在 XYZ 之後。插入只回傳給頁面，是否存回伺服器由頁面決定。適合文件中已有觸發字元時仍要插入內容的情境。
  - flow:
    - 測試資料：文件 `MAIL`（標題、段落「第一段內容」、段落「聯絡a@b.com」），觸發字串「@」，頁面同步回寫。
    - 操作：開啟示範宿主頁 → 等載入完成 → 將游標移到「第一段內容」行末（所見即所得與即時渲染點擊該段後按 End；分割預覽點擊編輯區後按 Ctrl+Home 再按 2 次下方向鍵與 End）→ 以每鍵 150 毫秒輸入「 @」 → 等頁面收到含「第一段內容 @」之回傳 → 等提示區出現 → 點擊「插入XYZ」 → 等頁面收到含 XYZ 之回傳 → 以每鍵 150 毫秒輸入 QQ → 等頁面收到含 XYZQQ 之回傳。
    - 驗證：
      1. 語意：①編輯區含「第一段內容 XYZQQ」；②編輯區仍含「a@b.com」；③頁面持有之內容含「a@b.com」且不含「 @XYZ」；④頁面持有之內容與最後回傳一致；⑤主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：只檢查游標前緊鄰之文字，不以全文搜尋（`removeHintTrigger`）。分割預覽之編輯區為原始碼，以鍵盤移至第 3 行。原測試：R09 於文件中段觸發且後文含相同字串（三模式）。

- **E2E-003**
  - title: 提示區開啟中伺服器回傳新內容時提示區關閉
  - description: 提示區開啟時按 Ctrl+S 儲存，伺服器回傳與目前不同的內容並由頁面寫回時，編輯器以伺服器的內容為準重新載入，原本開啟的提示區隨即關閉，避免插入到已被取代的位置；載入新內容不會回傳給頁面。儲存結果以頁面上方的「已儲存」確認，若仍需插入，請在新內容中重新輸入觸發字串。適合儲存後由伺服器整理內容的頁面。
  - flow:
    - 測試資料：預設文件 `ORI`，觸發字串「/ht」；儲存時伺服器於 0.3 秒後回傳 `SERVER`，上傳期間不鎖定。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後以每鍵 150 毫秒輸入「 /ht」 → 等頁面收到結尾為「/ht」之回傳 → 等提示區出現 → 按 Ctrl+S → 等儲存狀態為「已儲存」 → 經過 0.6 秒負向觀察窗。
    - 驗證：
      1. 語意：①提示區已關閉；②編輯區顯示 `SERVER`，所見即所得為「標題 第一段內容abc 伺服器回傳之內容」，其他模式前加「# 」；③提示區出現後頁面未再收到回傳；④主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：以鍵盤觸發儲存，因提示區以點擊外部關閉，若以點擊頁面按鈕觸發更新將無法分辨關閉原因（`spec/evidence/2026-10-04-host-probe1.log` 之 P6：Ctrl+S 與游標移動不關閉、點擊外部關閉）。整份內容被取代時組件先關閉提示區（`relaValue` 之 `hideHint`）。原測試：R09/R13 提示區開啟中父層載入新內容（三模式；原以程式改值，今改為儲存之伺服器回傳）。

- **E2E-004**
  - title: 提示區開啟中儲存鎖定時提示區關閉
  - description: 提示區開啟時按 Ctrl+S 儲存，頁面於上傳期間把編輯器設為唯讀，提示區隨即關閉，唯讀期間無法再經提示區插入，文件內容維持輸入觸發字串時的樣子，頁面不會收到變更，「復原 <Ctrl+Z>」停用。上傳完成、頁面顯示「已儲存」後恢復可編輯，可重新輸入觸發字串。適合儲存期間鎖定編輯的頁面。
  - flow:
    - 測試資料：預設文件 `ORI`，觸發字串「/ht」；儲存時上傳期間唯讀 3 秒，伺服器不寫回。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後以每鍵 150 毫秒輸入「 /ht」 → 等頁面收到結尾為「/ht」之回傳 → 等提示區出現 → 按 Ctrl+S → 等編輯區不可編輯 → 經過 0.6 秒負向觀察窗。
    - 驗證：
      1. 語意：①提示區已關閉；②編輯區結尾仍為「/ht」；③提示區出現後頁面未再收到回傳；④「復原」停用；⑤主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：鎖定分支關閉提示區（`applyEditable` 之 `hideHint`）；唯讀時之插入請求一律不插入並關閉（`insertValue`）。原測試：R15 提示區開啟中鎖定（三模式；原以程式鎖定，今改為 Ctrl+S 儲存）。

- **E2E-005**
  - title: 註冊多組觸發字串時依輸入者顯示提示區
  - description: 頁面可同時設定多組觸發字串，例如「/ht」與「/kw」；在文件末尾輸入空白與「/kw」後，提示區出現並標示目前觸發的是「/kw」，點擊「插入XYZ」後編輯器移除剛輸入的「/kw」並插入 XYZ。插入只回傳給頁面，是否存回伺服器由頁面決定。適合一個編輯器提供多種插入功能，例如範本與關鍵字。
  - flow:
    - 測試資料：預設文件 `ORI`，觸發字串「/ht」與「/kw」（`keyHint=/ht,/kw`），提示區顯示目前之觸發字串。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後輸入「 /kw」 → 等頁面收到結尾為「/kw」之回傳 → 等提示區出現 → 點擊「插入XYZ」 → 等頁面收到含 XYZ 之回傳。
    - 驗證：
      1. 語意：①提示區標示之觸發字串為「/kw」；②插入後編輯區含 XYZ 且不含「/kw」；③主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得；理由：觸發字串之判定由 vditor 提示模組處理（`hint/index.ts` 之 `getKey`），與模式無關，三模式之插入由 E2E-001 涵蓋。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：觸發字串陣列由 `keyHints` 轉為 vditor 之提示擴充，提示區之 `hint` 為目前觸發字串（slot props）。新增案例（舊測試無）。探測：`spec/evidence/2026-10-04-host-probe4.log` 之 P21。

- **E2E-006**
  - title: 觸發字串前非空白時不出現提示區
  - description: 觸發字串必須位於行首或空白之後才會叫出提示區；若直接接在文字後面，例如輸入「a/ht」，提示區不會出現，輸入的文字照常保留並回傳給頁面。需要提示區時，請先輸入空白再輸入觸發字串。適合內容中本來就會出現斜線等字元的文件，避免誤觸。
  - flow:
    - 測試資料：預設文件 `ORI`，觸發字串「/ht」。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後輸入「a/ht」 → 等頁面收到結尾為「a/ht」之回傳 → 經過 1.5 秒負向觀察窗。
    - 驗證：
      1. 語意：①提示區未出現；②編輯區結尾為「a/ht」；③主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得；理由同 E2E-005。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：vditor `getKey` 要求觸發字串在行首或其前一字元為空白。與 E2E-001 為出現與不出現之對稱路徑。新增案例（舊測試無）。探測：`spec/evidence/2026-10-04-host-probe4.log` 之 P22。

## 測試資料

| 變體 | 具名對象 | 取用方式 | 選它的理由 |
|---|---|---|---|
| 觸發字串 | 「/ht」、「@」 | `keyHint` | 多字元與單字元兩類；「@」與文件中電子郵件同字元 |
| 多組觸發字串 | 「/ht」與「/kw」 | `keyHint=/ht,/kw` | 驗證以實際輸入者判定 |
| 插入位置 | 文件末尾、文件中段 | `ORI`、`MAIL` | 中段且後文含相同字元為最易誤刪之情境 |
| 提示區開啟中之頁面動作 | 伺服器回傳新內容、儲存鎖定 | `saveReply=server`、`saveLock` | 整份取代與唯讀兩類 |

## 畫面元素對照

| 區域 | 元素 | 顯示文字／提示文字 | 定義位置 | 出現條件 | 觸發後行為 |
|---|---|---|---|---|---|
| 編輯器 | 提示區 | 頁面提供之內容，示範頁為「插入XYZ」按鈕 | `WVditorVue.vue` 模板 `slot content`；`test/host/index.html` | 可編輯且輸入觸發字串後停頓（行首或空白之後） | 點擊項目後移除觸發字串並插入、關閉提示區 |

## 規則摘要

- 提示區於回傳後偵測，與回傳共用防抖時間（預設 100 毫秒；分割預覽每次輸入即偵測）；提示區顯示時編輯區失焦，避免使用者以鍵盤繼續改動。
- 插入時只移除游標前本次輸入之觸發字串，游標已移離觸發字串時只插入（ADR-006）。「游標已移離」之分支不設案例：提示區開啟時編輯區已失焦、點擊編輯區即關閉提示區，使用者操作造不出「提示區開啟中而游標已移開」之狀態，屬防禦性分支（`removeHintTrigger`）。
- 整份內容被取代、或編輯器被設為唯讀時，提示區先關閉；唯讀或未就緒時之插入請求不插入。
- 提示區以點擊外部關閉，鍵盤不關閉。
- 各案例過程中主控台不得出現錯誤。
- 視覺：本專案不建像素標準圖（ADR-007），各案例視覺項為「無」。
