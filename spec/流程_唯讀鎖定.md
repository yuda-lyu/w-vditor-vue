# 流程_唯讀鎖定

## 觸發

頁面可隨時把編輯器設為唯讀，例如文件無編輯權限、或儲存上傳期間暫時鎖定。唯讀期間編輯區不可編輯，工具列之編輯類按鈕與「復原」「重做」停用，使用者的點擊與按鍵都不會改動內容；鎖定前最後一次輸入仍照常回傳。本文件涵蓋開啟即唯讀、載入中或載入後切換、儲存期間鎖定，以及唯讀時各種點擊與輸入。唯讀時之焦點與按鍵傳遞另見 `流程_唯讀時之焦點`。

- 入口：示範宿主頁（`spec/設計要點與取捨.md` 第二節），使用唯讀切換鈕與 Ctrl+S 儲存。
- 預設狀態：可編輯、文件 `ORI`、頁面同步回寫。

## 重要流程

- **E2E-001**
  - title: 開啟唯讀文件時不可編輯且工具列停用
  - description: 頁面以唯讀方式開啟文件時，編輯器載入完成後顯示文件內容，編輯區不可編輯，工具列的「粗體 <Ctrl+B>」等編輯類按鈕與「復原 <Ctrl+Z>」都呈停用，且在載入完成後的整段期間維持停用，不會短暫變為可用。唯讀不改動文件；需要編輯時由頁面切換為可編輯。適合只提供閱讀的文件或無編輯權限的使用者。
  - flow:
    - 測試資料：預設文件 `ORI`，唯讀（`editable=0`）。
    - 操作：開啟示範宿主頁 → 等載入完成 → 每 50 毫秒觀察一次、共 40 次。
    - 驗證：
      1. 語意：每次觀察皆：①編輯區顯示文件內容（所見即所得「標題 第一段內容abc 第二段內容xyz」，其他模式前加「# 」）；②編輯區為不可編輯；③「復原」停用；④「粗體」停用；⑤主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：三模式各有延後寫入復原紀錄之計時（vditor `wysiwyg/afterRenderEvent.ts`、`ir/process.ts`、`sv/process.ts`），觀察 2 秒涵蓋之。現行版本就緒時之復原紀錄只有 1 筆，「復原」不會被啟用（`node_modules/vditor/src/ts/undo/index.ts` 之 `addToUndoStack` 於 2 筆以上才啟用），此案為原始版本缺陷（就緒前已寫入空白紀錄，紀錄 2 筆而啟用「復原」）之防退化：關閉唯讀監看之突變（N14）不使此案轉紅，原始版 39748e1 三模式皆紅（`spec/evidence/2026-10-04-red-run.json`）。原測試：R07 editable=false（三模式）。

- **E2E-002**
  - title: 頁面自備語系資料之唯讀文件工具列停用
  - description: 頁面自備語系資料並以唯讀方式開啟文件時，編輯器載入完成後同樣不可編輯，編輯類按鈕與「復原 <Ctrl+Z>」在整段期間維持停用。適合內網部署之唯讀閱讀頁。
  - flow:
    - 測試資料：預設文件 `ORI`，唯讀，頁面自備語系資料（`i18n=1`）。
    - 操作：同 E2E-001。
    - 驗證：
      1. 語意：同 E2E-001 之①～⑤。
      2. 視覺：無。
    - 模式：只測所見即所得；理由：自備語系資料只改變載入時序，與模式無關。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：原測試：R07 editable=false 且給予 settings.i18n。

- **E2E-003**
  - title: 唯讀文件載入後收到資料時「復原」仍停用
  - description: 唯讀文件在編輯器載入完成後才收到頁面送來的資料時，編輯器顯示新資料，工具列的「復原 <Ctrl+Z>」仍維持停用，使用者無法以復原回到先前內容。資料送達不需任何操作。適合以唯讀方式非同步載入文件的閱讀頁。
  - flow:
    - 測試資料：預設文件 `ORI`，唯讀，開頁後 2.5 秒送達 `NEW_SHORT`（標題「新內容」）。
    - 操作：開啟示範宿主頁 → 等載入完成 → 等編輯區顯示新內容 → 經過 1 秒負向觀察窗。
    - 驗證：
      1. 語意：①編輯區顯示「新內容」，即時渲染與分割預覽為「# 新內容」；②「復原」停用；③主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：未編輯時之載入清空復原紀錄（`relaValue` 之 `loadValue(true)`），載入後紀錄只有 1 筆，「復原」不會被啟用；此案為原始版本缺陷之防退化（原始版 39748e1 三模式皆紅，`spec/evidence/2026-10-04-red-run.json`）。已編輯後於唯讀期間載入而重新啟用「復原」者見 E2E-008。原測試：R07 editable=false 且就緒後組件外變更（原只測所見即所得，今擴為三模式以求對稱）。

- **E2E-004**
  - title: 點擊「設為唯讀」後無法輸入，「設為可編輯」後恢復
  - description: 在頁面上方操作列點擊「設為唯讀」，編輯區即不可編輯、編輯類按鈕停用，此時點擊編輯區並打字都不會改變內容，頁面也不會收到變更；按鈕文字變為「設為可編輯」，點擊後編輯區恢復可編輯，在文件末尾輸入的字照常出現並回傳給頁面。切換不改動內容。適合依權限或流程暫時鎖定編輯的頁面。
  - flow:
    - 測試資料：預設文件 `ORI`，頁面同步回寫。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊「設為唯讀」 → 點擊編輯區 → 輸入 Z → 經過 0.6 秒負向觀察窗 → 點擊「設為可編輯」 → 點擊編輯區、按 Ctrl+End 後輸入 Y → 等頁面收到結尾為 Y 之回傳。
    - 驗證：
      1. 語意：①點擊「設為唯讀」後編輯區不可編輯、「粗體」停用；②輸入 Z 後內容不變、頁面未收到回傳；③點擊「設為可編輯」後編輯區可編輯；④Y 接於文件末尾；⑤頁面持有之內容與最後回傳一致；⑥主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：點擊頁面按鈕時焦點已移至該按鈕；焦點在編輯區內時之鎖定見 `流程_唯讀時之焦點`。原測試：R15 就緒後父層切換 editable（原只測所見即所得、以程式切換，今擴為三模式並改為點擊）。

- **E2E-005**
  - title: 載入中收到唯讀權限時就緒即唯讀
  - description: 頁面開啟時先以可編輯建立編輯器，權限資訊在編輯器載入期間才送達並要求唯讀時，編輯器載入完成即為唯讀，編輯類按鈕停用，不會先出現可編輯的狀態。權限送達不需任何操作。適合權限需向伺服器查詢的頁面。
  - flow:
    - 測試資料：預設文件 `ORI`，開啟時可編輯，開頁後 50 毫秒送達唯讀權限（`permAt=50&permTo=0`）；排版引擎之回應延後 1 秒。
    - 操作：開啟示範宿主頁 → 等載入完成 → 經過 1 秒觀察窗。
    - 驗證：
      1. 語意：①權限送達當下編輯器仍在載入（前提）；②編輯區不可編輯；③「粗體」停用；④主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得；理由：就緒時套用唯讀之程式不分模式（`onEditorReady` 之 `applyEditable`），三模式之唯讀套用由 E2E-001 涵蓋。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：與 E2E-006 為對稱路徑。原測試：R15 初始化期間把 editable 改為 false。

- **E2E-006**
  - title: 載入中收到編輯權限時就緒即可編輯
  - description: 頁面開啟時先以唯讀建立編輯器，權限資訊在載入期間送達並允許編輯時，編輯器載入完成即可編輯，編輯類按鈕可用。權限送達不需任何操作。適合預設唯讀、確認權限後才開放編輯的頁面。
  - flow:
    - 測試資料：預設文件 `ORI`，開啟時唯讀，開頁後 50 毫秒送達可編輯權限（`permAt=50&permTo=1`）；排版引擎之回應延後 1 秒。
    - 操作：同 E2E-005。
    - 驗證：
      1. 語意：①權限送達當下編輯器仍在載入（前提）；②編輯區可編輯；③「粗體」可用；④主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得；理由同 E2E-005。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：原測試：R15 初始化期間把 editable 改為 true。

- **E2E-007**
  - title: 輸入後立即儲存鎖定時最後輸入照常回傳
  - description: 在編輯區輸入後立即按 Ctrl+S 儲存，頁面於上傳期間把編輯器設為唯讀，上方顯示「上傳中…」；鎖定前最後輸入的字照樣回傳給頁面，編輯區保留這些字，而唯讀期間「復原 <Ctrl+Z>」與編輯類按鈕維持停用，不會因為編輯器事後記錄這次輸入而重新啟用。上傳完成顯示「已儲存」後恢復可編輯。適合儲存期間鎖定編輯的頁面。
  - flow:
    - 測試資料：預設文件 `ORI`，頁面同步回寫；儲存時上傳期間唯讀 3 秒（`saveLock=3000`），伺服器不寫回。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End → 以每鍵 150 毫秒輸入 ab → 輸入 c → 立即按 Ctrl+S → 等頁面收到結尾為 abc 之回傳 → 經過 0.5 秒負向觀察窗。
    - 驗證：
      1. 語意：①儲存狀態為「上傳中…」；②編輯區不可編輯；③「復原」停用；④「粗體」停用；⑤編輯區為開啟時內容接 abc；⑥頁面持有之內容與最後回傳一致且結尾為 abc；⑦主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：鎖定前最後輸入可能於鎖定後才回傳（JSDoc `editable`）；vditor 回傳與寫入復原紀錄於同一計時器，回傳後之復原鈕重新啟用由唯讀監看改回。原測試：R15 輸入後隨即鎖定（三模式；原以程式鎖定，今改為 Ctrl+S 儲存）。

- **E2E-008**
  - title: 鎖定期間收到伺服器內容，解鎖後可復原
  - description: 輸入後按 Ctrl+S 儲存，上傳期間編輯器為唯讀；伺服器回傳整理後的內容時，編輯器改為顯示該內容，仍維持唯讀且「復原 <Ctrl+Z>」停用。上傳完成、頁面顯示「已儲存」並恢復可編輯後，「復原」轉為可用，點擊一次即回到伺服器回傳前自己編輯的內容。是否接受伺服器整理後的內容由使用者以復原決定，存回伺服器仍由頁面處理。適合伺服器會整理或合併內容的儲存流程。
  - flow:
    - 測試資料：預設文件 `ORI`，頁面同步回寫；儲存時上傳期間唯讀 2.5 秒，伺服器於 0.8 秒後回傳 `SERVER`（第二段改為「伺服器回傳之內容」）。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區、按 Ctrl+End 後輸入 abc → 等頁面收到結尾為 abc 之回傳 → 停頓 0.6 秒 → 按 Ctrl+S → 等編輯區顯示伺服器內容 → 經過 1 秒負向觀察窗 → 等儲存狀態為「已儲存」 → 點擊「復原 <Ctrl+Z>」。
    - 驗證：
      1. 語意：①鎖定期間編輯區顯示 `SERVER`，所見即所得為「標題 第一段內容abc 伺服器回傳之內容」，其他模式前加「# 」；②編輯區不可編輯；③「復原」停用；④「粗體」停用；⑤解鎖後「復原」可用；⑥復原後編輯區為輸入 abc 後之內容；⑦主控台無錯誤。
      2. 視覺：無。
    - 模式：三模式各一輪。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：唯讀期間載入時 vditor 延後寫入復原紀錄並啟用「復原」，由唯讀監看改回；已編輯故保留復原紀錄。原測試：R15 已編輯後鎖定、鎖定期間父層送來新內容（三模式；原以程式鎖定與改值，今改為 Ctrl+S 儲存之伺服器回傳）。

- **E2E-009**
  - title: 唯讀時點擊待辦核取方塊與圖片無效
  - description: 唯讀文件中的待辦清單核取方塊，點擊後勾選狀態不會改變，內容與頁面持有的內容都不變；點擊文件中的圖片也不會出現可修改圖片網址的編輯框。唯讀時不改動文件。適合含待辦清單或圖片之文件的唯讀閱讀。
  - flow:
    - 測試資料：文件 `TASKS`（標題、未勾之「待辦一」、已勾之「待辦二」、圖片），唯讀。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊第一個核取方塊 → 經過 0.8 秒負向觀察窗 → 點擊圖片 → 經過 0.5 秒負向觀察窗。
    - 驗證：
      1. 語意：①編輯區內有 1 個以上核取方塊（前提）；②點擊後核取狀態不變；③編輯區內容不變；④頁面持有之內容仍為 `TASKS` 原文；⑤頁面未收到回傳；⑥「復原」停用；⑦編輯區內有圖片（前提），點擊圖片後無可見之編輯框輸入欄；⑧主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得與即時渲染；理由：分割預覽之編輯區為原始碼，無核取方塊與圖片元素。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：vditor 之點擊處理不檢查唯讀（`wysiwyg/index.ts`、`ir/index.ts`），組件攔截核取方塊與圖片之點擊（`guardLock`）。原測試：R15 唯讀時點擊核取方塊與圖片（兩模式）。

- **E2E-010**
  - title: 唯讀時點擊內容下方空白處不新增段落
  - description: 唯讀文件中點擊最後一段下方的空白處，不會新增空白段落；之後於頁面上方操作列點擊「設為可編輯」，在文件末尾輸入的字會接在原本最後一段之後，而不是落在多出來的空行。唯讀時不改動文件。適合唯讀閱讀後再開放編輯的頁面。
  - flow:
    - 測試資料：文件 `BELOW`（標題「標題」、段落「末段文字」），唯讀，頁面同步回寫。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊編輯區內最後一段下方之空白處 → 經過 0.5 秒負向觀察窗 → 點擊「設為可編輯」 → 點擊最後一段 → 按 Ctrl+End → 輸入 Q → 等頁面收到結尾為 Q 之回傳。
    - 驗證：
      1. 語意：①點擊空白處後編輯區之段落數不變；②最後一筆回傳去除結尾空白為「# 標題」空一行接「末段文字Q」；③主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得與即時渲染；理由：分割預覽之編輯區無點擊處理（vditor `sv/index.ts` 無點擊監聽）。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：vditor 於點擊編輯區本身時新增空段落（`wysiwyg/index.ts`、`ir/index.ts`），組件攔截點擊對象為編輯區本身者。原測試：R15 唯讀時點擊內容下方空白處（兩模式）。

- **E2E-011**
  - title: 唯讀時於內容中之輸入框打字不回傳
  - description: 唯讀文件內若含網頁輸入框，以 Tab 鍵移到該輸入框後打字，輸入框本身照常顯示所打的字，但文件內容與頁面持有的內容都不變，頁面不會收到任何變更。唯讀時不改動文件。適合內容含 HTML 元素之文件的唯讀閱讀。
  - flow:
    - 測試資料：文件 `FORM`（標題、HTML 輸入框、「末段文字」），唯讀。
    - 操作：開啟示範宿主頁 → 等載入完成 → 點擊搜尋框 → 連按 Tab 直到焦點位於編輯區內之輸入框 → 輸入 Z → 經過 1 秒負向觀察窗。
    - 驗證：
      1. 語意：①以 Tab 鍵可到達編輯區內之輸入框（前提）；②頁面未收到回傳；③頁面持有之內容仍為 `FORM` 原文；④主控台無錯誤。
      2. 視覺：無。

- **E2E-012**
  - title: 鎖定後點擊停用之「標題」不吞掉最後輸入
  - description: 輸入後立即按 Ctrl+S 儲存使編輯器鎖定，此時誤點工具列已停用的「標題 <Ctrl+H>」按鈕，按鈕不會有反應，鎖定前最後輸入的字仍會照常回傳給頁面，不會因此遺失。適合儲存期間鎖定編輯、使用者可能誤觸工具列的頁面。
  - flow:

      1. 語意：①點擊前「標題」為停用（前提）；②頁面恰收到 1 次回傳且結尾為 Z；③主控台無錯誤。
      2. 視覺：無。
    - 模式：只測所見即所得與即時渲染；理由：分割預覽每次輸入即同步回傳，不受標題鈕清除計時器之影響。
    - 清理：不變動資料；瀏覽器每案全新。
    - 備註：vditor 之標題鈕先清除渲染計時器才檢查停用（`toolbar/Headings.ts`），組件攔截停用中之工具列按鈕（`guardLock`）。防抖 600 毫秒確保點擊落在回傳之前。原測試：R15 輸入後隨即鎖定再點擊停用之標題鈕（兩模式；原以程式鎖定，今改為 Ctrl+S 儲存）。

## 規則摘要

- 唯讀之完整性由組件於事件層補齊：攔截編輯區內之按鍵、核取方塊與圖片與編輯區本身之點擊、表單控制項之輸入、停用中之工具列按鈕；被 vditor 重新啟用之工具列與編輯區即時改回（ADR-004）。
- 點擊與按鍵類之防護以頁面之唯讀設定判斷（一鎖定即生效），焦點與輸入類以「唯讀已套用」判斷，使鎖定瞬間之失焦與輸入法提交仍交 vditor。
- 鎖定前之最後輸入可能於鎖定後才回傳，照常回傳（JSDoc `editable`）。
- 各案例過程中主控台不得出現錯誤。
- 視覺：本專案不建像素標準圖（ADR-007），各案例視覺項為「無」。
