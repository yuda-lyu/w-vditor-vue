## 1. 封裝第三方編輯器：先對標官方封裝、權責分清（使用者裁示，2026-10-04）

- **緣由**：2026-10-04 使用者連續指出——第二輪在組件內加「10 秒回拋紀錄」去處理父層延遲回寫，等於在組件內做 CRDT 協調；再把其邊界情形寫成「已知限制」，是權責不清與亂猜；要求上網並讀姊妹套件，查清一般封裝之作法。
- **動手前先對標**：讀官方或主流封裝之實際原始碼，並以同條件實測對標（本機姊妹套件 w-ckeditor-vue 內含 CKEditor 5 Vue 2 封裝之原始碼；另可讀 `@tinymce/tinymce-vue`、`vue-quill-editor`）。
- **定位**：本組件是**單一編輯者之輸入組件**，與原生 input、CKEditor／TinyMCE／Quill 官方 Vue 封裝同類，只做三件事——編輯器就緒時載入父層 `value` 並顯示、內容一變更即回拋、依 `editable` 鎖定（鎖定一致性由組件維持）。回拋資料之去向（同步其他組件、上傳伺服器）、上傳期間之鎖定、多組件同步、延遲或亂序回寫之協調，全屬父層；多組件／多人共編須父層與組件層皆支援 CRDT，本組件不支援，**不得以組件內推測邏輯（回拋紀錄、時間窗）代替**。
- **遇「父層回寫／外部改值／鎖定」類需求**：先問「這是組件還是父層之責任」，對標官方封裝作法後再定方案；判斷屬父層責任者，於程式註解寫明裁決，避免日後被父層需求帶偏。
- **不得把自己設計之機制所產生之邊界情形稱為「已知限制」**：一般封裝沒有之問題，先檢討自己之設計。
- **動手前先把生命週期（Vue 組件與被封裝編輯器各自之初始化前後）與資料事件逐一標成狀態表再寫碼**（現行定案：單一 `stage`，created → creating → ready（或 failed）→ destroyed，ADR-002、ADR-008）。
- **改本組件前必讀**：`WVditorVue.vue` 之 watch 區塊裁決註解、`isEcho`、`st.input` 與 `guardLock` 註解；裁決全文見 `spec/設計要點與取捨.md` ADR-001 與〈四、裁決紀錄〉。新增行為須同步補 spec 案例與測試（三模式對稱，排除須寫理由），改完跑 `npm test`。
- **對外審查**：派審期間（審查者未回報前）不得改動受審之檔（原始碼與測試），否則審查者讀到新內容、意見針對改後版本（見 `sgud/exp/experience.md` 2026-11-22 條）。

## 2. 內網／離線部署（對外說明在 `README.md`〈For intranet / offline deployment〉）

- 作法：把 `node_modules/vditor/dist` 複製到自架站台，`settings.cdn` 指向**含 `dist` 之上一層**；離線站之 `dist` 須與 umd 內嵌之 vditor 同版（`js/lute/lute.min.js` 隨版本而異）。資源清單與大小見 README。
- 驗證法：以 playwright 攔截所有非本機請求，開啟編輯器並涵蓋各模式與內容語法，確認零外部請求（2026-08-19 實測 7/7；語系檔可改以 `settings.i18n` 傳物件而完全不發請求）。vditor 升版後須重驗。
- 語系或排版引擎不可達時，組件停在載入圖示（`spec/流程_編輯器載入與關閉.md`）。
